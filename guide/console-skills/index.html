항상 routing도 전체 스킬 본문을 모든 요청에 넣는 뜻이 아닙니다. 스킬 설치·정책 저장은 실행 권한, 외부 자격이나 사용자 승인을 새로 주지 않습니다. 이전 로딩 원칙과 공식 레지스트리 안내는 이미지 날짜를 함께 확인하세요.

설치된 스킬 조회

  1. 설정 → 스킬 → 설치된 스킬을 열어 기본 제공 스킬과 추가 설치 스킬을 분리해 봅니다. 이름이 같아도 source-qualified 스킬 ID가 다르면 다른 항목입니다.
  2. 각 항목의 소스 ID, 필수/선택, 활성 설정, 검증 통과/차단을 확인합니다. 부분 조회와 빈 목록, 조회 실패는 서로 다릅니다.
  3. 새로고침으로 현재 inventory를 다시 읽습니다. 저장된 활성 표시는 현재 요청에서 실제로 로딩됐다는 뜻이 아니므로 선택 결과를 별도로 확인합니다.

일반 사용자는 설치 메타데이터를 읽을 수 있으나 설치·삭제·정책 저장은 검증된 관리자만 할 수 있습니다. 관리자는 변경 전 활성·사용 중 요청·기존 설치 기록을 확인합니다.

공식 카탈로그 검색·설치

  1. DreamLabs 스킬 카탈로그를 열고 저장된 목록 다시 읽기를 수행합니다. 검색 결과는 로컬에 보관된 메타데이터이며 이 조회만으로 원격 다운로드가 일어나지 않습니다.
  2. 스킬 ID와 정확한 버전을 선택해 상세 보기로 호환성·출처를 검토합니다. 같은 ID의 여러 버전은 별도 항목입니다.
  3. 관리자는 선택한 버전의 설치 미리보기를 요청하고 대상·파일 검증·현재 설치·확인 경계를 읽습니다. 설치 확인을 한 번 수행한 뒤 영수증과 실제 설치 트리를 다시 조회합니다.

미리보기는 설치가 아닙니다. 입력 ZIP과 다운로드는 저장 전에 안전 검사를 거치며, 차단된 패키지는 다른 워커 작업을 멈추는 정상 설치로 취급하지 않습니다. 설치 뒤에도 사용 가능성과 로딩을 별도로 설정합니다.

프로젝트 Git 소스와 검사·동기화

스킬 소스 및 인증에서 프로젝트 Git 소스의 ID·주소·설정 상태와 write-only 자격을 관리합니다. 새 checkout 이름은 서버가 소스 ID에서 정하며 기존 checkout 경로를 임의로 바꾸지 않습니다. 저장 뒤 revision과 같은 소스의 재조회로 확인합니다.

스킬 소스 검사 및 갱신을 열 때는 저장 상태만 읽습니다. 프로젝트 원격 검사나 공식 카탈로그 검사를 눌러야 네트워크 검사가 시작됩니다. 프로젝트 후보 commit 확인과 정확한 후보 동기화는 별도 작업이고, 공식 카탈로그 갱신은 설치를 뜻하지 않습니다. 검사 실패나 결과 불명에서 자동 활성화·재시도하지 않습니다.

관리자: 로컬 ZIP 업로드

  1. 로컬 스킬 패키지 업로드에서 승인된 작은 시험 ZIP 하나를 선택합니다. 패키지 크기와 형식, 루트 SKILL.md, 경로 안전 검사를 확인합니다.
  2. 미리보기는 서버의 비공개 staging만 만들며 설치 목록에는 나타나지 않아야 합니다. 제시된 스킬 ID·내용 해시·출처 revision·기존 목적지 충돌을 검토합니다.
  3. 정확한 대상을 확인한 경우에만 한 번 설치합니다. 요청이 진행 중이거나 응답이 유실되면 미완료 업로드 다시 읽기 → 상세 및 복구에서 보존 요청과 실제 트리·영수증을 대조합니다. 같은 ZIP을 중복 설치하지 않습니다.

로컬 ZIP은 공식 Registry 출처가 되지 않습니다. 업로드 후에도 스킬은 자동 활성·로딩되지 않습니다. 이 화면으로 원격 출처를 자동 게시하지도 않습니다.

정확한 버전 업데이트·설치 제거

공식 카탈로그의 정확한 버전 업데이트는 현재 설치와 후보의 버전·해시·로컬 수정 여부를 미리 비교합니다. 관리자 확인 뒤 한 번 적용하고 영수증·설치 트리를 다시 읽습니다. 업데이트는 사용 가능성/로딩 정책을 조용히 바꾸지 않습니다. 로컬 수정이 있거나 비교 대상이 달라지면 중단하고 재검토합니다.

설치된 스킬 → 설치 제거는 Registry 설치와 로컬 업로드 설치를 다른 소유 목록으로 보여 줍니다. 정확한 설치 ID·버전 또는 업로드 ID·트리 해시를 확인한 뒤 미리보기/확인/결과 읽기를 수행합니다. 기본 제공 스킬과 다른 소스 소유 파일은 삭제 대상이 아닙니다. 사용 중 요청, 로컬 수정, 재설치 세대 충돌은 제거를 막을 수 있습니다. 중단된 제거는 보존된 요청의 상세 및 복구에서 정착시키며, 이전 영수증만으로 나중에 설치된 동일 경로를 다시 지우지 않습니다.

주입 정책·선택 미리보기·예산

  1. 설치된 스킬 → 주입 정책에서 스킬별 사용 가능성과 로딩 모드를 따로 편집합니다. 모드는 항상 routing/자동/명시 선택이고, 사용 불가와 별도입니다.
  2. 관리자는 여섯 예산 항목(전체/스킬별 routing bytes, routing tokens, 선택 본문 bytes/tokens, 선택 스킬 수)을 서버 범위 안에서 조정합니다. routing 카드가 예산을 넘는 저장은 거부되고 스킬 본문을 몰래 잘라 넣지 않습니다.
  3. 전역 지침은 공백을 포함한 원문 그대로 저장하고 명시적으로 비워 지울 수 있습니다. 암호·토큰·개인 정보는 넣지 않습니다. 한 영역 저장은 다른 미저장 초안을 덮지 않아야 합니다.
  4. 정책 revision·policy/inventory/content digest, 정확한 스킬 ID·논리 경로와 선택 미리보기를 읽어 어떤 routing/본문이 선택되거나 제외됐는지 확인합니다. 미리보기는 가상 요청이며 실제 작업·승인·모델 호출을 만들지 않습니다.

저장 성공은 해당 영역의 응답과 canonical 재조회 값이 일치해야 합니다. 이전 버전/해시로 선택 미리보기를 반복하지 않고 새 inventory를 읽습니다. 필수 스킬은 비활성화할 수 없습니다.

자동 업데이트 동의·결과

설치된 스킬 → 자동 업데이트에서 전역 동의와 설치 항목별 동의를 따로 저장하고 revision·정확한 설치 식별자를 재조회합니다. 지금 카탈로그 확인은 설치된 Registry 스킬을 일회성으로 확인합니다. 접수 응답은 최종 성공이 아니며 결과 목록의 진행·완료·차단을 별도로 읽습니다. 새 스킬 설치, 자동 활성화 또는 RRA 요청은 만들지 않습니다. 작업 결과가 불명확하면 같은 요청을 자동 재전송하지 않습니다.

실패와 결과 불명

상태안전한 처리
목록 부분/조회 실패보이는 항목이 전부라고 단정하지 않습니다. 원인과 차단 수를 기록하고 정식 재조회합니다.
revision·해시 충돌정확한 ID·버전·소스·설치 트리를 다시 읽습니다. 예전 확인을 재사용하지 않습니다.

권한 상실보호된 지침·자격·초안을 화면에서 제거하고 새 계정 권한을 확인합니다.

직접 테스트와 화면 캡처

  1. 정확한 후보 이미지가 적용된 시험 워커에서 관리자·일반 사용자로 설치 목록, 기본 제공/추가 분류와 변경 버튼 권한을 비교합니다.
  2. 가상 스킬 하나로 공식 카탈로그 미리보기→설치→사용 가능성→로딩 모드→새 요청 선택을 각 단계의 재조회로 확인합니다.
  3. 승인된 시험 ZIP과 버전 업데이트/제거는 정확한 ID·해시·영수증을 기록하고 원복합니다. 현재 운영 스킬은 삭제하지 않습니다.
  4. 부분 목록, revision 충돌, 결과 불명과 권한 감소에서 보호 내용 정리·중복 변경 방지를 확인합니다.
  5. 데스크톱과 모바일의 실제 목록·미리보기·확인·결과 화면을 비밀값 없이 촬영합니다.

정확한 후보 이미지가 적용된 시험 워커와 시험 스킬·카탈로그/ZIP, 관리자·일반 사용자를 준비합니다. 현재 운영 스킬은 삭제하지 않습니다.

실행 순서

  1. 설치된 스킬의 기본 제공/추가 분류, ID·출처·검증 상태와 부분 조회를 확인합니다.
  2. 시험 스킬의 미리보기·설치·활성·로딩·실제 요청 선택을 각각 구분해 재조회합니다.
  3. 버전 업데이트·로컬 ZIP·정확 설치 제거의 대상/영수증/현재 트리를 비교합니다.
  4. 자동 업데이트 동의와 일회성 카탈로그 확인·결과를 분리합니다.
  5. 충돌·결과 불명·권한 상실 뒤 중복 설치/삭제가 없는지 보고 데스크톱·모바일 화면을 촬영합니다.

통과 기준

설치가 자동 활성·로딩·실행 권한이 되지 않고 정확한 설치 ID와 canonical 결과가 일치합니다.
