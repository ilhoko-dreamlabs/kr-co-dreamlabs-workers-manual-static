2026.10.13 RRA 대화 이어가기·진행 표시·동시 실행 후보

외부 요청을 일반 대화 초안으로 이어가기, 공개 진행 상태 복구, 관리자 동시 실행 상한을 보완한 이미지 후보의 기능과 검사 방법입니다.

로컬 이미지 빌드·격리 검사 확인 / 운영 미적용확인일 2026.10.13읽기·검사 약 5분
바로 이동
이미지와 적용 상태RRA에서 일반 대화 초안 만들기공개 진행 상태 다시 보기관리자 동시 실행 설정사이드바 버전과 언어확인된 검사와 제한적용 후 재현 검사화면 증거 범위직접 테스트
로컬 이미지 검사 완료 · 운영 미적용이 항목은 앞선 Connector 기록 호환성 이미지 다음 소스로 만든 별도 불변 이미지 후보입니다. 이미지 빌드와 격리 검사는 통과했지만 원격 Registry 등록, 서버 이미지 배치, 업데이트 제안과 지정 워커 적용은 하지 않았습니다. 아래 조작은 후보 이미지의 구현·검사 기준이며 현재 운영 화면에서 이미 사용할 수 있다는 뜻이 아닙니다.

이미지와 적용 상태

2026.10.13은 정식 제품 버전 번호가 아닙니다. 콘솔에 표시되던 v0.1.0이나 날짜만으로 불변 이미지를 구별하지 않습니다. 정확한 소스·이미지 식별은 비공개 배포 기록에서 관리합니다.

같은 날짜의 운영 조회에서는 worker0과 worker00이 앞선 Connector 호환성 이미지로 건강하게 실행 중이었습니다. 이 새 후보는 어느 워커에서도 실행 중인 것으로 확인되지 않았습니다. 이미지 공급과 운영 적용은 별도 결정·검사 단계입니다.

RRA 응답에서 일반 대화 초안 만들기

후보 구현에서는 외부 세션 → Remote Request API에서 완료·차단 등 최종 상태의 요청과 응답을 열고, 응답 옆 대화로 이어가기를 선택합니다. 대화 제목, 첫 요청 초안, 필요한 경우 프로젝트를 확인한 뒤 대화 만들기를 누릅니다. 만들어진 일반 Chat에는 Remote Request에서 이어진 대화와 원본 요청 보기가 표시되고, 원래 RRA History는 읽기 전용으로 남습니다. 같은 연결을 다시 선택할 때는 관련 대화에서 기존 초안으로 돌아갈 수 있도록 설계했습니다.

대화를 만드는 것만으로 첫 요청이 실행되지 않습니다. 제목·초안을 검토한 뒤 일반 Chat에서 별도로 보내야 합니다. 첨부파일은 복사되지 않고 RRA 키 권한·실행 환경·도구 권한도 새 대화에 승계되지 않습니다. 원본이 바뀌었거나 삭제됐다면 새로고침 안내를 확인하고 중복 생성을 임의로 반복하지 않습니다.

공개 진행 상태 다시 보기

RRA 외부 세션의 실행과정 보기와 일반 Chat 진행 표시가 브라우저 연결이 끊기거나 다른 세션으로 이동해도 보존된 공개 실행 기록에서 다시 시작하도록 보완됐습니다. 다시 열면 먼저 현재 스냅샷을 읽고 이후 새 이벤트를 받아 진행 상태를 갱신합니다. 늦게 도착한 이전 세션 이벤트는 현재 세션 화면에 섞이지 않아야 합니다. RRA의 최종 응답은 보존된 정식 History 결과를 기준으로 표시합니다.

이 기능은 사용자에게 공개 가능한 실행 진행 정보입니다. 내부 추론 원문이나 비공개 도구 프로토콜을 공개하지 않습니다. 브라우저를 다시 연결하는 동작이 같은 작업을 다시 실행하거나 새 요청을 만드는 동작이어서도 안 됩니다. 과거에 기록되지 않은 진행 정보를 소급해서 만들어 내지는 않습니다.

관리자 Adapter 동시 실행 상한

관리자는 후보 적용 후 설정 → 런타임 → Execution Admission → Adapter 동시 실행 상한에서 각 Adapter의 설정값·권장값·유효값을 대조합니다. 지원 범위는 최대 16이며 권장 초기값은 2입니다. 실제 동시에 실행 가능한 수는 Worker 전체·lane·Adapter 상한 중 가장 작은 값으로 제한됩니다. 0은 해당 Adapter의 새 실행을 멈추는 값입니다.

이전에 2가 저장돼 있다면 예전의 더 높은 값을 추측해 자동 복원하지 않습니다. 관리자가 원하는 값을 명시적으로 저장하고 다시 읽어야 합니다. 상한을 높여도 이미 실행 중인 작업, 모델·제공자 한도, 권한과 운영 자원 제한이 사라지지 않습니다. 운영 값 변경은 배포 후 관리자 판단과 별도 시험이 필요합니다.

사이드바 버전과 한국어·영어 표시

후보 UI는 로드된 이미지의 출처 정보가 유효하면 사이드바에 Worker 이미지 버전을 표시하도록 보완했습니다. 출처가 없거나 읽기 오류가 나면 알 수 없음·오류 상태로 구분해야 합니다. 관련 대화 Context와 진행 상태 문구의 한국어·영어 표시도 함께 보완했습니다. 표시된 버전은 실제 실행 이미지 확인의 단서이며, 운영 담당자는 워커 이름·이미지·건강 상태를 별도로 대조합니다.

확인된 검사와 제한

깨끗한 소스의 전체 개발 검증 454건 통과와 Wiki 검사 후 만든 로컬 이미지에서 파일 1,384개의 출처·무결성을 확인했습니다. 비루트·읽기 전용·네트워크 차단 격리 검사는 2개 초과 Adapter 상한 보존, RRA/Chat 공개 진행 기록, 앞선 Connector 효과 기록 호환성과 기본 이벤트 수신 꺼짐을 확인했습니다. 이미지에는 운영 인증·상태 파일이 들어 있지 않습니다. Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2와 Node 22.23.3은 앞선 이미지에서 바뀌지 않았습니다.

이 검사는 운영 워커의 실제 Chat 연결·진행 표시·관리자 설정 저장을 검증한 결과가 아닙니다. Registry 등록, 서버 배치와 지정 워커 적용도 아직 없으므로 운영 성공, 화면 캡처 확보 또는 자동 업데이트 정책 변경으로 해석하지 않습니다.

적용 후 재현 검사

  1. 운영 담당자가 정확한 후보 이미지의 대상 워커 적용·건강·보존 데이터를 확인하고, 기존 이미지와 구분합니다.
  2. 최종 RRA 요청·응답 하나에서 대화로 이어가기를 눌러 제목·첫 요청 초안·프로젝트를 검토합니다. 생성 후 원본 History, 새 일반 Chat과 원본 요청 보기를 대조하고, 자동 실행·첨부 전송·권한 승계가 없는지 확인합니다. 같은 연결을 반복해도 대화가 중복되지 않아야 합니다.
  3. RRA와 Chat 작업의 공개 진행 표시를 확인한 뒤 브라우저 연결을 끊고 다시 엽니다. 기존 스냅샷·새 이벤트·최종 History와 실제 Task 결과가 맞고, 이전 세션 이벤트가 섞이거나 작업이 재실행되지 않아야 합니다.
  4. 관리자 시험 환경에서 Adapter 상한을 승인된 2 초과 값으로 저장·재조회하고 새 요청 동시 실행 한도를 확인합니다. Worker·lane 제한, 0의 신규 실행 차단, 기존 저장값 2의 비자동 복원도 대조한 뒤 시험 설정을 복원합니다.
  5. 한국어·영어와 좁은 화면에서 연결 버튼·진행 표시·사이드바 버전을 실제로 촬영하고, 값이 로드된 실행 이미지와 일치하는지 확인합니다.

이 절차는 향후 운영 수용 기준이며 지금 통과한 결과가 아닙니다.

화면 증거 범위

새 후보의 운영 화면 캡처 미확보입니다. 기존 워커의 화면은 이 이미지의 RRA 연결 버튼·진행 표시·Adapter 설정·사이드바 버전 증거로 재사용하지 않습니다. 실제 적용 후 데스크톱·좁은 화면의 한국어·영어 표시와 클릭 결과를 촬영하고, 워커·이미지·시각·결과를 기록합니다. 계정·API 키·대화 내용·내부 이미지 주소는 공개 캡처에서 가립니다.

시작 조건

이 이미지는 로컬 빌드·격리 검사만 확인된 운영 미적용 후보입니다. 아래 검사는 정확한 이미지가 승인된 시험 워커에 적용되고, 최종 RRA 응답·시험 Chat·관리자 시험 계정이 준비된 뒤에만 실행합니다.

실행 순서

  1. 최종 RRA 응답의 대화로 이어가기를 선택해 대화 제목·첫 요청 초안·프로젝트를 확인하고 대화 만들기 뒤 원본 요청 보기와 관련 대화를 대조합니다.
  2. 새 Chat이 자동 실행되지 않고 첨부·RRA 키 권한이 승계되지 않는지 확인합니다. 같은 원본에서 다시 열어 중복 생성 여부를 봅니다.
  3. RRA와 Chat의 공개 진행 상태를 확인한 뒤 브라우저를 재연결하고 세션을 바꿔 스냅샷·새 이벤트·정식 History 최종 결과를 대조합니다.
  4. 관리자 시험 환경에서 Adapter 상한을 2 초과 값으로 저장·재조회하고 Worker·lane 제한과 0의 신규 실행 차단을 확인합니다. 시험값을 복원하고 사이드바 버전·한국어/영어·좁은 화면을 촬영합니다.

통과 기준

원본 RRA는 보존되고 일반 Chat 초안은 한 번 만들어지며 명시적으로 보내기 전에는 실행되지 않아야 합니다. 진행 재연결이 작업을 재실행하거나 비공개 추론을 노출해서는 안 됩니다. 상한은 명시적 저장 뒤 보존되고 기존 저장값 2를 추측으로 높이지 않아야 합니다.

남길 증거

시험 워커·정확한 내부 이미지·적용 시각, RRA/Chat 연결 및 최종 Task 상태, 공개 진행 이벤트와 History 대조, 관리자 설정 시작·저장·복원값, 데스크톱/모바일 실제 화면을 기록합니다. 공개 자료에서 계정·키·내부 주소는 가립니다.
