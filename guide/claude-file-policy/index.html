Claude 파일 한도와 오류 확인

관리자 파일 한도 설정이 Claude의 지원되는 MCP 파일 응답에 적용되는 범위와 실패 원인별 확인 절차입니다.

아래 화면은 실제 후보 컴포넌트의 로컬 합성 캡처이며 운영 화면·기능 결과는 확인 전입니다.

바로 이동
적용 범위관리자 설정새 실행에서 확인오류별 조치다시 요청하기 전후보 화면직접 테스트
2026.10.20 후보 · 운영 적용 전이 절차는 별도 Claude 파일 제한 개선 이미지를 정확히 실행하는 워커에서 검증합니다. 14:21(KST)에는 이미지 빌드·격리 검사와 Registry 식별, 서버 이미지 단독 배치와 관리 워커 8개의 대상 제안까지 확인했습니다. 그 당시 실제 적용과 운영 파일 결과는 없었고 이후 상태는 재조회해야 합니다. 아래 캡처는 제품 컴포넌트를 로컬 Chromium에 합성 설정/오류로 표시한 것으로 운영 캡처가 아닙니다.

어떤 파일에 적용되는가

설정 → 시스템 → 파일 업로드의 파일 하나의 최대 크기 (MiB)는 기존 Console·Remote Request API·Mattermost의 대화 첨부파일에 더해, 이번 후보에서 Claude의 지원되는 MCP 파일 응답에도 적용됩니다. 판단 기준은 Base64 문자열의 길이가 아니라 디코딩한 원본 파일 크기입니다. 한도를 넘는 파일 결과를 Worker가 허용한다는 뜻은 아니며, 외부 서비스·Claude 자체의 별도 제한도 유지됩니다.

프로필 원본/변환 이미지와 스킬 패키지 합계는 이 필드와 별개입니다. 결과 파일 전송·파일 개수·전체 저장 공간·다른 제공자의 응답과 모델 내부 메모리도 이 변경으로 무제한이 되지 않습니다. 이 이미지의 검증·공급 상태를 먼저 확인하세요.

관리자: 현재 한도와 저장 결과 확인

  1. 관리자 계정으로 설정 → 시스템 → 파일 업로드를 열고 현재 적용 값·출처·설정 범위를 기록합니다. 일반 사용자는 이 설정값을 조회·변경할 수 없습니다.
  2. 변경이 허가된 시험 워커에서만 원하는 값을 표시된 범위 안에 입력하고 저장을 선택합니다. 다시 열거나 새로고침해 저장된 유효값을 확인합니다. 다른 관리자의 변경 충돌이면 초안을 보존한 상태에서 최신값을 비교합니다.
  3. 저장은 새 업로드와 다음 Claude 실행부터 적용됩니다. 진행 중인 실행은 시작 때 고정된 값·리비전을 사용하고, 기존 첨부파일은 삭제되지 않습니다. 변경 전/후 실행의 시작 시각·한도를 섞어 판정하지 않습니다.

안전한 파일로 새 Claude 실행 시험

관리자가 허가한 격리 시험에서 개인·고객 자료가 없는 파일과 승인된 MCP 경로를 사용합니다. 예를 들어 대화 첨부파일 한도 2 MiB에서 원본 3 MiB 파일을 Claude가 반환하도록 요청하면, 지원되는 파일 응답에는 CONTEXT_NATIVE_OUTPUT_LIMIT의 reason=file-size가 남아야 합니다. 5 MiB 한도에서 원본 3 MiB와 정확히 5 MiB인 파일은 Worker의 이 수신 검사에서 통과해야 합니다. 이들은 로컬 합성 loopback 검사에서 확인된 경계이며 실제 외부 서비스 성공을 보장하지 않습니다.

각 시험마다 워커의 정확한 실행 이미지·건강, 설정 유효값과 저장 리비전, Claude 실행 시작 시각, 원본 파일 크기, Task 최종 상태, Chat/RRA 안내와 기술 코드를 나란히 기록합니다. 파일 결과를 만든 도구 호출의 효과는 별도로 확인합니다. 대화에 토큰·비공개 원본 파일을 붙이지 않습니다.

오류 코드에 맞춰 확인하기

기술 코드·상황사용자에게 보이는 뜻과 다음 확인
CONTEXT_NATIVE_OUTPUT_LIMIT; reason=file-size이번 실행에 고정된 원본 파일 한도를 넘었습니다. 표시된 MiB와 원본 크기를 대조하고, 관리자에게 설정 확인을 요청하거나 파일을 줄입니다. 설정을 올려도 외부 서비스 한도는 별도입니다.
reason=transport-capacity 또는 reason=frame-size전송·메시지의 안전 한도를 넘었습니다. 원본 전체를 받지 못했을 수 있으므로 파일 크기 초과로 단정하지 않습니다. 응답 범위를 줄이고 관리자에게 코드를 전달합니다.
CONTEXT_NATIVE_PROCESS_CLOSED; reason=truncated-frame응답 도중 종료되었습니다. 실행 상태와 기술 코드를 확인합니다.
CONTEXT_NATIVE_PROTOCOL_INVALID응답 형식 문제입니다. 이 코드만으로 파일 크기 초과라고 결론 내리지 않습니다. 첫 오류가 별도로 기록됐는지 확인합니다.
UPLOAD_POLICY_UNAVAILABLE설정을 읽지 못해 실행을 시작하지 않았습니다. 관리자에게 설정 상태 확인을 요청합니다.

이번 수정은 최초 크기·전송 오류가 종료 시 일반 프로토콜 오류로 덮이던 문제도 바로잡습니다. Chat과 RRA의 한국어·영어 안내는 원인을 구분하며 오류 원문에 비밀 메타데이터를 붙이지 않아야 합니다.

다시 요청하기 전

자동 재시도하지 않습니다. 파일을 반환한 도구가 외부 시스템에서 자료를 이미 만들거나 바꿨다면 원본 서비스에서 실제 효과를 확인한 뒤 재요청 여부를 결정합니다. 단순히 Worker 설정을 높이거나 파일을 나눠도 서비스 자체의 한도, 파일 형식, 권한 문제는 따로 남을 수 있습니다. 반복 실패 때는 Task·시각·첫 오류 코드를 운영 담당자에게 전달하세요.

화면 증거 범위

세 장 모두 이미지 후보의 실제 설정/오류 컴포넌트·스타일을 로컬 Chromium에서 합성 데이터로 렌더링했습니다. 한국어·영어 안내와 모바일 설정은 별도 제품 브라우저 검사에서 확인됐습니다. 운영 워커의 새 설정 화면, 실제 제공자 파일 결과 및 RRA 운영 화면은 미촬영·미검증입니다. 적용 후 비밀값을 가린 실제 화면과 실행 결과로 보완해야 합니다.

시작 조건

2026.10.20 후보를 정확히 실행하는 승인된 시험 워커, 관리자·일반 사용자 계정, 고객 자료가 없는 안전한 시험 파일과 지원되는 MCP 경로가 필요합니다. 14:21(KST) 서버 배치·8개 제안은 확인됐지만 당시 적용·운영 결과는 없었으므로 현재 실행 이미지를 재조회합니다.

실행 순서

  1. 관리자로 설정 → 시스템 → 파일 업로드를 열어 첫 한도의 현재 유효값·출처 및 네 필드를 확인하고, 일반 사용자의 설정 조회·변경 거부를 대조합니다.
  2. 승인된 시험 워커에서 한도를 저장·재조회하고 변경 전 진행 중 Claude 실행에는 옛 값, 다음 실행에는 새 값이 쓰이는지 리비전과 시작 시각으로 대조합니다.
  3. 한도 아래·초과·정확한 경계의 안전한 원본 파일을 지원되는 MCP 경로로 한 번씩 반환해 Task·Chat/RRA 안내와 원본 크기를 대조합니다.
  4. file-size, transport-capacity, frame-size, protocol-invalid를 같은 오류로 합치지 않고 첫 오류가 보존되는지 검사합니다.
  5. 도구의 외부 효과를 원본에서 확인한 뒤 재요청 여부를 결정하고 시험 설정을 복원합니다.

통과 기준

원본 파일 바이트 기준 한도가 다음 Claude 실행부터 적용되고 기존 첨부와 진행 중 실행은 유지됩니다. 초과 파일은 file-size로 끝나며 뒤늦은 protocol-invalid가 첫 원인을 덮지 않아야 합니다. 자동 재시도나 비밀 메타데이터 노출이 없어야 합니다.

남길 증거

비공개 기록에 워커·정확 이미지·시각·설정 값과 리비전·원본 파일 크기·Task와 도구 호출 횟수·첫/최종 오류·Chat/RRA 실제 화면·복원값을 남깁니다. 비밀과 고객 자료는 가립니다.
