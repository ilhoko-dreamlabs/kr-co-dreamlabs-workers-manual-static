이번 이미지의 변경

GitLab 작업 실패를 로컬 선택·자격 저장소 문제, GitLab 제공자 거부, 변경 효과가 불확실한 쓰기 결과로 나누어 진단합니다. 준비되고 승인된 Connector가 있으면 그 경로를 우선합니다. Connector가 준비되지 않았더라도 서버에 설정된 자격과 독립된 승인 검사를 통과하면 GitLab REST 경로로 작업할 수 있습니다. 일반 GET 읽기는 읽기 전용으로 처리합니다. GitLab 작업 사용법과 예제에서 기대 결과를 확인하세요.

자격·권한 경계

대체 경로는 Connector 권한을 무제한 우회하는 기능이 아닙니다. 요청한 계정·프로젝트와 리소스 범위, 읽기 전용 정책, 사용 중지·권한 회수 상태를 다시 검사합니다. 서버 자격이 있어도 실제 계정과 GitLab 프로젝트 권한이 맞지 않으면 실행할 수 없습니다. 공개 화면에서 토큰 값이나 내부 GitLab 주소를 요구하지 않습니다. 각 워커의 실제 설정과 제공자 권한은 적용 뒤 별도 운영 검사로 확인해야 합니다.

안전한 대체·재시도

처음 경로가 변경 효과 없음으로 확실하게 끝났을 때만 승인된 다른 경로를 한 번 사용할 수 있습니다. GitLab에 쓰기가 전달됐는지 알 수 없는 경우에는 자동으로 같은 변경을 다시 보내지 않습니다. 동일 작업을 재시작하거나 기록을 다시 읽을 때도 중복 변경을 막도록 보완했습니다. 결과 불명이라면 원래 Task·대상 리소스·제공자 기록을 조회해 효과를 확인하고 운영 담당자와 다음 조치를 결정하세요. 실패 카드를 성공으로 기록하거나 새 요청을 반복해서 보내지 마세요.

스킬과 RRA 안내

이번 이미지에는 gitlab-work 번들 스킬과 RRA 요청 처리 안내가 포함됩니다. 스킬은 승인된 경로의 사용 순서와 안전한 결과 확인을 설명하며, 스킬 설치나 선택만으로 자격·프로젝트 권한이 생기지 않습니다. RRA의 요청자와 대상 권한도 그대로 확인해야 합니다. 실제 워커에서 스킬 선택·GitLab 결과가 함께 확인되기 전까지는 운영 통과로 표시하지 않습니다.

이전·후속 이미지와의 경계

이번 변경은 GitLab 실행 경로와 관련 안내입니다. 직전 이미지의 Codex 공개 요약, Action 식별, 맨 아래로 버튼, 업데이트 완료 안내는 포함되지만 이번 신규 UI 개선으로 다시 세지 않습니다. 이 이미지에는 기존 Git 연결의 기능·외부 리소스 제한이 남아 있습니다. 같은 날짜의 별도 GitLab·GitHub 계정 권한 방식 이미지가 그 기준을 바꾸며, 앞선 이 이미지로 소급하지 않습니다. 번들 Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2는 그대로입니다. 새 서비스·승인 화면·자격 데이터베이스·데이터 마이그레이션은 이 이미지에는 없습니다. Worker 소스의 원격 main 통합이나 운영 전체 적용도 이 이미지 검사로 입증되지 않습니다.

확인된 검사

깨끗한 소스 기준 개발 검사 470건 통과·실패 0·차단 0과 이미지 내부 1,420개 파일의 출처·무결성 검사를 확인했습니다. 패키징된 GitLab REST 경로, 재시작 후 중복 방지, 읽기 전용 처리, 결과 불명 쓰기 차단, 비밀정보 가림, 번들 스킬을 네트워크 차단·읽기 전용 격리 환경에서 검사했습니다. 로컬 자원 부족 상황에서 한 컨테이너에 합친 CLI 검사 세 번이 시간 제한으로 끝났으며 원인은 확정되지 않았습니다. 이후 같은 30초 제한으로 앱과 세 CLI를 각각 순차 검사해 모두 통과했고 실패 로그도 보존했습니다. Registry와 서버 배치 이미지의 식별이 검증본과 일치하고 관리 워커 8개의 대상 제안·정상 상태·기존 이미지 복귀 대상을 확인했습니다. 실제 GitLab 계정·제공자 결과와 지정 워커의 새 이미지 기능은 아직 검증하지 않았습니다.

적용 후 직접 테스트하기

  1. 지정 워커의 정확한 실행 이미지·건강·기존 자료 보존을 먼저 확인합니다. Registry 등록이나 제안만으로 적용을 판정하지 않습니다.
  2. 권한 있는 시험 프로젝트에서 읽기 전용 목록 요청을 한 번 실행해 Task 최종 상태와 실제 GitLab 응답의 프로젝트·자료를 대조합니다. 준비된 Connector가 있으면 우선 사용됐는지도 기록합니다.
  3. Connector가 준비되지 않은 허용된 시험 환경에서 서버 자격·계정·프로젝트 범위가 모두 맞을 때만 대체 경로의 읽기 결과를 확인합니다. 비활성·회수·범위 밖·읽기 전용 제한은 거부돼야 합니다.
  4. 승인된 격리 시험 프로젝트에서만 안전한 변경 요청과 제공자 결과를 대조합니다. 결과 불명 쓰기를 같은 요청으로 다시 보내지 않고 원래 리소스의 효과를 먼저 조회합니다. 재시작·재진입 후 중복 변경도 별도 시험합니다.
  5. gitlab-work 스킬의 선택 기록과 RRA 경로의 대상·권한·최종 결과를 확인합니다. 스킬 선택을 GitLab 권한 확인으로 대신하지 않습니다.

워커·정확한 내부 이미지·시각, 시험 계정/프로젝트 범위, Task 및 제공자 결과, 경로 선택·거부 사유·중복 효과 여부를 비공개 기록에 남깁니다. 공개 자료에는 토큰·내부 주소·고객 자료를 넣지 않습니다.

화면 증거

새 이미지의 운영 화면 캡처 미확보입니다. 이번 변경에는 새 Console 화면이 없으며 18:37(KST) 조회 시 지정 워커에서 새 이미지 실행이 확인되지 않았습니다. 적용 뒤에는 기존 세션의 요청·최종 결과·오류 진단과 스킬 선택 상태를 실제 화면에서 촬영해 기능 판정에 연결합니다. 2026년 10월 1일 과거 캡처를 이 이미지의 운영 증거로 재사용하지 않습니다.

실행 순서

  1. 빌드·Registry·서버 배치·제안·실제 적용·기능 결과를 별도 단계로 기록하고 대상 워커의 정확한 실행 이미지·건강을 확인합니다.
  2. 권한 있는 시험 프로젝트에서 GET 읽기를 수행해 원본 자료와 Task 최종 상태를 대조합니다. 준비된 Connector 우선과 독립 승인 REST 대체 경로를 구분합니다.
  3. 계정·프로젝트·읽기 전용·비활성·회수 제한을 승인된 격리 시험에서 각각 확인합니다.
  4. 확실한 무효과 실패만 승인된 다른 경로를 한 번 사용하는지 검사합니다. 결과 불명 쓰기 자동 재전송과 재시작 후 중복 변경은 차단돼야 합니다.
  5. gitlab-work 번들 스킬·RRA 안내의 선택과 실제 권한·제공자 결과를 별도로 확인합니다.

통과 기준
