시작 조건과 권한

  1. 대상 Worker의 이름·정확한 실행 이미지·건강·현재 계정 역할을 기록합니다. 일반 사용자는 표시된 읽기 전용 정보만 보며, 비밀값·정책·프로세스 변경은 검증된 관리자에게 제한됩니다.
  2. 관리자 시험은 보존할 기존 값·revision, 가상 시험 값, 변경 후 복구 방법을 먼저 정합니다. 실제 운영 값을 임의로 바꾸어 화면을 확인하지 않습니다.
  3. 로그인·권한 상실은 구분합니다. 인증 소멸 401은 재로그인이 필요하고, 관리자 권한 축소 403은 보호된 상세와 초안을 닫거나 지워야 합니다.

11월 로컬 이미지에 포함된 화면을 실제 적용 워커의 결과로 표시하지 않습니다. 개발·이미지·운영 단계를 먼저 대조하세요.

설정 목록 읽기

/console → 설정에서 항목의 연결 상태를 읽고 원하는 상세를 명시적으로 엽니다. 현재 소스는 환경 변수, Worker Base, 런타임·실행 프로필, 실행 허용 정책, 프로세스 수명주기, 어댑터 인증·API 자격, 커넥터, 스킬, 시스템 이벤트, 예약, Worker 업데이트와 공개 페이지 등을 각각 별도 영역으로 제공합니다. 연결 항목이라도 모든 하위 조작이 가능한 것은 아닙니다. 기존 Console 사용이 표시된 상세는 그 경로로 이동합니다.

런타임 선택 화면에서 Codex CLI·Claude Code·Kimi의 설치 버전과 로컬 업데이트 후보 조회는 명시적 읽기입니다. 개별 CLI 업데이트 동작은 제공하지 않으며 전체 Worker 릴리스 절차를 따릅니다. 후보가 다르게 표시돼도 더 새 버전이라고 단정하지 않습니다. 실행 프로필의 모델·추론·속도 선택은 현재 어댑터가 제공하는 지원 목록을 다시 읽고 결정합니다. 저장된 과거 선택은 남아도 지금 실행 가능한 조합이라는 뜻은 아닙니다.

관리자: 환경 변수와 비밀값

  1. 설정 → 환경 변수를 열고 현재 revision과 저장된 key, 마스킹 상태, 실제 주입 출처를 읽습니다. 비밀값 원문은 화면으로 돌아오지 않습니다.
  2. 한 값을 바꾸려면 명시적으로 새 값을 입력합니다. 이미 저장된 비밀은 화면의 마스킹 상태를 유지하면 보존됩니다. 빈칸이나 삭제를 같은 뜻으로 해석하지 말고 표시된 조작을 확인합니다.
  3. 변경 저장 전 목록에서 삭제될 key를 별도로 확인합니다. 저장 뒤 mutation receipt의 적용/미변경과 새 revision, canonical 재조회 key·마스킹을 대조합니다. 마스킹된 값만으로 비밀 원문의 동일성을 증명하지 않습니다.
  4. 가져오기는 내용 미리보기와 합치기/교체를 구분합니다. 마스킹 내보내기는 복구 가능한 비밀 백업이 아닙니다. 선택된 어댑터의 실제 주입 표시는 key·출처·차단 이유만 읽고 값을 노출하지 않습니다.

결과 불명 또는 revision 충돌에서 같은 PUT을 자동 반복하지 않습니다. 입력은 보존하고 canonical 상태와 영수증을 대조한 뒤 새 결정을 합니다. 변경 버리기는 브라우저 입력만 지우며 불명확한 서버 변경을 되돌리는 작업이 아닙니다.

Worker Base·런타임·프로필

Worker Base는 작업 경로, 공통 지침과 새 요청의 기본 실행 권한을 관리합니다. 관리자만 읽고 revision에 묶인 설정 저장 뒤 canonical 재조회로 확인합니다. 기존 접수 요청의 정책 스냅샷은 소급 변경되지 않습니다. 런타임 정보의 inventory·활성 선택·실행 재료 미리보기는 읽기 전용이며, 미리보기는 실제 실행이 아닙니다.

런타임 어댑터에서는 현재 선택/세대, 준비 상태, 설정·유효·권장 동시 실행 용량을 구분합니다. 권장은 현재 설정이나 강제 한도가 아닙니다. 관리자 변경은 대상 준비 확인과 별도 확인 뒤 새 요청부터 적용됩니다. 실행 프로필은 이름·설명·어댑터별 지원 옵션·기본값과 사용 중인 연결의 영향을 확인합니다. 없는 매핑을 자동 생성하거나, 다른 프로필에 묶인 요청의 선택을 조용히 바꾸지 않습니다. 상세 절차는 실행 프로필 안내를 참고하세요.

실행 허용 정책·프로세스 수명주기

실행 허용 정책은 Worker 전체/요청 경로/어댑터의 동시 실행 상한을 보여 주고 Queue·실행 이력을 읽습니다. 한 번에 한 대상의 승인된 한도만 편집하고 정책 저장 → canonical 재조회로 판정합니다. Queue 항목의 취소·재실행 권한을 이 화면의 한도 편집과 혼동하지 않습니다. 이력에서 상태·시각·시도·어댑터·결과만 표시하며 원본 프롬프트나 비밀 자료를 보여 주지 않습니다.

프로세스 수명주기는 Worker 소유/잔여/좀비 프로세스와 재시작 준비 상태를 진단합니다. 잔여 프로세스 종료와 재시작 의도는 관리자 별도 확인이 필요합니다. 재시작 의도 요청만으로 Worker가 재시작된 것은 아니며 실행은 외부 Manager가 담당합니다. 결과가 불명확하면 새로고침으로 실제 상태를 읽고 같은 요청을 반복하지 않습니다.

Codex·Claude·Kimi 인증 화면

상세관리자 조작·판정
Codex 구독 인증인증 상태 확인 후 한 번의 Codex 로그인 시작을 선택합니다. 표시된 주소·코드는 제공자 화면에서만 다루고, 진행 중인 시도는 명시적으로 취소할 수 있습니다. 이전 시도의 늦은 응답이 새 시도를 덮으면 안 됩니다. 상태가 인증됨이어도 실제 모델 응답은 별도입니다.
Claude 장기 인증브라우저 setup-token 연결 또는 승인된 수동 관리 토큰을 선택합니다. 연결·제거·상태 재조회가 분리되어 있으며 비밀값은 다시 표시하지 않습니다. 필요하면 브라우저 인증은 기존 Console에서 열기를 사용합니다.
Kimi 인증·모델 설정Moonshot API key의 존재·설정 출처와 고정 모델 계약을 읽기 전용으로 확인합니다. 키 편집은 기존 환경 변수 경로로 이동합니다. 프로세스 환경 변수가 저장값보다 우선할 수 있으며, 설정됨은 실제 제공자 인증 성공이 아닙니다.

인증 주소·코드·토큰·key는 공개 캡처나 매뉴얼에 적지 않습니다. 실제 제공자 요청 결과는 수행한 경우에만 통과로 기록합니다.

관리자: HTTP 어댑터 API 자격증명

설정 → API 자격증명은 여섯 종량제 HTTP 어댑터의 기본 자격증명 존재와 저장/프로세스 출처를 보여 줍니다. 관리자는 정확한 어댑터 하나를 선택해 primary key를 교체하거나 별도 확인으로 제거합니다. 서버가 저장 key를 정하고 원문은 다시 표시하지 않습니다. revision 충돌이면 새 상태를 읽고 재결정합니다. 저장 key를 지워도 호스트의 프로세스 환경값은 그대로일 수 있으며, 보조 key나 다른 어댑터 설정은 유지됩니다. 실제 모델 인증과 비용·권한은 이 화면의 성공 영수증으로 확정되지 않습니다.

예약·시스템·업데이트·공개 페이지

예약 설정은 저장된 일정과 실행 이력·수동 실행의 별도 판정을 제공합니다. 시스템 이벤트는 수신기·허용 발행자·처리 영수증을 관리하고 스킬 자동 업데이트는 별도 동의 화면으로 이어집니다. Worker 업데이트는 실행 중인 이미지와 정확한 제안 상태, 정책·요청·완료를 구분합니다. 제안이 보이는 것과 적용·재시작·자료 보존 성공은 별개입니다. 최신 v4 업데이트 코드는 소스 단계라 이 후보 이미지의 현재 버튼으로 취급하지 않습니다.

공개 페이지는 프로필 소개·이미지와 고정 필드의 미리보기·확인·되돌리기를 분리합니다. 공개 전 익명 결과와 개인정보를 검토하고, 실제 공개 동작을 수행했다면 정확한 URL과 반영 revision을 재조회합니다. 화면 편집이나 미리보기만으로 게시됐다고 기록하지 않습니다.

직접 테스트와 화면 증거

  1. 정확한 이미지가 적용된 시험 워커에서 관리자·일반 사용자로 설정 목록을 촬영하고 표시/변경 권한을 비교합니다.
  2. 환경 변수의 가상 key, 실행 제한의 한 값, 시험용 프로필을 각각 저장·재조회·복원합니다. 비밀값 원문과 운영 설정은 촬영하지 않습니다.
  3. Codex·Claude·Kimi의 설정 존재, 실제 로그인, 실제 모델 응답을 서로 다른 결과로 기록합니다. 외부 계정이 없다면 차단 또는 미실행입니다.
  4. 결과 불명/충돌/권한 감소에서 중복 제출이 없고 보호 내용이 지워지는지 확인합니다.
  5. 데스크톱·390px 모바일의 실제 설정 화면을 정확한 이미지와 연결해 캡처합니다.

운영 화면 미촬영 · 현재 로컬 후보의 운영 화면 증거는 없습니다. 390px 로컬 합성 화면에서는 긴 설정 설명이 오른쪽으로 잘리는 현상을 확인했습니다. 모바일 사용성은 수정·재검증이 필요합니다. 이 절차는 적용 후 테스트 기준입니다.

시작 조건

정확한 11월 후보가 승인된 시험 워커에 적용된 경우 관리자·일반 사용자와 복원 가능한 가상 설정을 준비합니다. 미적용이면 미실행입니다.

실행 순서

  1. 새 설정 목록에서 환경·Worker Base·런타임·인증·시스템·업데이트의 실제 연결 상태와 역할을 읽습니다.
  2. 환경 가상 key와 실행 제한 한 값을 각각 명시적으로 저장·재조회·복원하고 secret 원문은 기록하지 않습니다.
  3. Codex·Claude·Kimi의 구성 표시와 실제 인증/모델 결과를 분리합니다.
  4. 충돌·결과 불명·권한 상실에서 같은 쓰기 재전송과 보호 정보 노출이 없는지 봅니다.
  5. 데스크톱·390px 모바일 화면을 비밀값 없이 촬영합니다.

통과 기준

서버 revision·값과 실제 새 요청 결과가 일치하고 역할·오류 경계가 유지됩니다. 소스 단계만으로 운영 통과를 기록하지 않습니다.
