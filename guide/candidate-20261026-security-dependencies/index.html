직전 이미지에서 달라진 점

10월 25일 이미지는 Claude Code Plan의 관리자용 장기 OAuth 인증과 기본 꺼진 Console Next 검증 기반을 포함했지만, 당시 생산 의존성 감사에서 중간 심각도 2건·높은 심각도 2건이 남아 있었습니다. 이번 별도 이미지에서는 그 네 패키지 계열과 필요한 하위 의존성을 올려 루트·Standalone 앱·이미지 내부의 생산 의존성 npm 감사 0건을 확인했습니다. 이전 이미지의 감사 결과를 소급해 0건으로 바꾸지 않습니다.

이 변경은 기존에 저장된 관리 토큰의 발급·검증을 수행하거나 새 인증 화면을 추가하지 않습니다. 장기 인증의 조작 순서·만료 표기·파일 로그인 관계는 직전 후보 사용법을 따르며, 실제 계정·모델 요청 수용은 여전히 남아 있습니다.

화면·데이터·인증 호환

이번 소스 차이에는 Console 화면, 사용자 조작, 권한, 보존 데이터 형식, 포트·서비스 소유권 또는 CLI 버전 변경이 없습니다. Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2가 유지됩니다. 기존 파일 로그인과 Worker 관리 장기 토큰 동작은 패키지 교체 후에도 별도 인증 회귀 검사로 확인했습니다.

따라서 이번 보완만을 위한 새 설정 절차나 화면 캡처는 없습니다. 다만 10월 25일에 추가된 장기 인증 패널의 실제 운영 화면 캡처와 계정·모델 결과는 아직 확보되지 않았습니다. 기존 Portable ZIP은 이 이미지로 갱신되지 않았으며 해당 배포 형태의 호환성·오프라인·업데이트 보존은 별도 검증이 필요합니다.

검증한 경계

정확한 깨끗한 소스에서 전체 검사 516건 통과·실패 0·차단 0을 확인했습니다. 두 body-parser 계열은 각각 정상 gzip, 잘못된 JSON의 400, 과도한 본문의 413, 압축 데이터 뒤 잔여 바이트, 이후 정상 응답의 다섯 경우를 격리 HTTP 검사로 통과했습니다. 생산 의존성 회귀 검사는 취약한 중첩 복사본도 찾는 11개 항목을 통과했습니다.

동일 이미지에서 자산 1,695개의 출처·식별, 비어 있는 인증 자료, 관리 인증 검사 11건, 네트워크를 막은 임시 기동의 건강 응답 200·Wiki 준비·인증 없는 관리자 조회 거부 401을 확인했습니다. 실제 운영 요청·제공자 모델 호출·장기 토큰 발급을 실행한 결과는 아닙니다.

남은 위험과 미확인

루트의 개발 도구 의존성 경고 7건은 별도 범위로 남았습니다. 이번 생산 이미지에는 해당 개발 도구가 복사되지 않았지만, 저장소 전체 감사가 0건이라는 뜻은 아닙니다. 운영체제 패키지 스캔도 이번 검사에 포함되지 않았습니다.

최종 전체 검사 전에는 서로 다른 검사 집계 실패가 기록됐습니다. 검사 건수 변경에 따른 집계 조건과 시험 포트 문제는 검증 도구에서 보정해 같은 안전 검사로 다시 실행했습니다. Wiki의 간헐 실패 원인은 아직 확정되지 않았습니다. Kimi 기동 검사는 처음 두 번 30초 제한에 걸렸고, 별도 진단 뒤 4.3초 및 원래 30초 검사에서 통과했습니다. 이를 운영 Kimi 요청 성공으로 해석하지 않습니다.

10월 26일 01:13(KST) 제안 확인 당시 지정 워커 적용·실제 업무 결과는 없었습니다. 업데이트 제안은 이후 상태가 바뀔 수 있으므로 실행·수용 여부는 새 읽기 증거가 생길 때까지 미확인으로 남깁니다.

지정 워커 적용 뒤 확인할 순서

  1. 업데이트 전에 대상 워커·현재 실행 이미지·건강·기존 세션과 설정·자격 자료 보존 상태를 비공개 기록으로 확인합니다. Registry 등록이나 제안만으로 워커 적용을 판정하지 않습니다.
  2. 승인된 정확 이미지를 적용한 뒤 새 실행 이미지·건강·Wiki 준비·기존 자료가 그대로인지 확인합니다. 실제 작업 전후의 인증 자료 원문은 읽거나 공개 기록에 남기지 않습니다.
  3. 격리 시험 워커에서만 정상·잘못된 JSON·용량 초과·압축 본문 후속 정상 응답을 양쪽 파서 경로에서 확인합니다. 예상 400/413과 이후 정상 응답을 구분합니다.
  4. 기존 Claude Plan 장기 인증 화면의 권한·CLI 상태와 승인된 무해한 새 실행의 최종 결과를 별도 판정합니다. Kimi와 다른 어댑터도 승인된 안전한 요청의 실제 최종 상태로 확인합니다.
  5. 생산 npm 감사 0건, 개발 도구 경고·OS 스캔·Portable ZIP 미검증을 서로 다른 항목으로 기록합니다. 실패한 변경 요청은 원래 결과를 확인한 뒤 재시도합니다.

이 절차는 향후 수용 기준이며 아직 어느 지정 워커에서도 실행한 통과 기록이 아닙니다.
