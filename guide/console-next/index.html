시작과 화면 전환

  1. 대상 워커의 HTTPS 주소에서 /console을 열고 필요한 경우 로그인합니다. 후보가 정확히 적용된 워커라면 Console Next가 기본으로 열립니다.
  2. 왼쪽의 최근 세션·프로젝트와 화면의 대시보드를 선택합니다. 선택한 항목의 제목·상태·내용이 실제 대상과 일치하는지 확인합니다.
  3. 설정·예약 등 이 화면에 아직 연결되지 않은 기능은 상단의 설정·예약 등 기존 기능 링크를 선택합니다. 직접 주소는 /console?ui=legacy입니다.

로그인이 만료되면 새로 로그인한 뒤 같은 항목을 다시 확인합니다. 모의 데이터나 이전 워커의 캡처를 현재 항목으로 판단하지 않습니다.

일반 대화와 대기 요청

  1. 새 대화를 선택하고 제목을 입력하거나 기본 제목으로 만듭니다. 이 단계는 빈 Chat 세션만 만들며 요청을 실행하지 않습니다.
  2. 대화 입력란에 시험용 문장을 적고 적용할 실행 프로필을 확인한 뒤 명시적으로 전송합니다. 진행 표시는 공개 실행 내역이며 최종 답변은 완료 뒤 정식 세션 기록에서 확인합니다.
  3. 이미 실행 중인 세션에서는 요청이 대기 요청에 저장될 수 있습니다. 항목 하나를 열어 수정·저장하거나 실행을 선택합니다. 삭제는 확인 단계를 거치며 대기열 항목만 지웁니다.
  4. 실행 중 작업을 멈출 때는 취소를 요청하고 최종 종료 상태를 다시 확인합니다. 취소 접수 자체를 완료로 기록하지 않습니다.

유지보수 보류·동시 실행 제한에서는 대기 요청이 보존될 수 있습니다. 충돌 안내가 나면 최신 대기열을 다시 읽고 결정하며, 결과가 불확실한 전송을 자동으로 반복하지 않습니다.

RRA 대화 읽기·이어가기

Remote Request API 그룹에서 기존 RRA 세션을 열면 원격 요청의 메시지·공개 진행·최종 상태를 볼 수 있습니다. RRA 원본 화면의 입력란에서 일반 Chat 요청을 직접 보내지는 않습니다. 최종 응답을 확인한 뒤 일반 대화 초안으로 이어가기를 선택하면 연결된 새 Chat 초안이 준비되지만 자동 실행되지는 않습니다.

외부 프로그램이 같은 RRA 세션 자체에서 후속 질문을 보내려면 다른 절차가 필요합니다. RRA v1의 sessionId 후속 요청 또는 개발 워커의 sessionAnchorId 후속 요청을 참고하세요. 일반 Chat ID, RRA 세션 ID, outbound anchor를 서로 바꿔 쓰지 않습니다.

프로젝트와 대시보드

대시보드의 Action·Operations·Projects·Knowledge·PARA 보기에서 출처·관측 시각과 부분 상태를 함께 읽습니다. 카드에 정확한 세션 열기 또는 프로젝트 열기가 있으면 해당 항목을 열고 실제 제목·ID를 대조합니다. 이동 목적지가 연결되지 않은 카드의 비활성 안내는 임의의 항목으로 이동한 결과가 아닙니다.

프로젝트 상세에서는 분류, 진행/완료, 활성/보관, 지침 revision, 멤버 세션을 별도로 확인합니다. 새 프로젝트나 프로젝트 설정에서 명시적으로 저장하고, 프로젝트 세션 만들기는 세션만 생성합니다. 기존 세션 연결/해제와 보관·복원·삭제는 서로 다른 작업입니다. 프로젝트 삭제는 세션 대화를 지우는 작업이 아니며 조건에 따라 차단될 수 있습니다.

변경 후 표시 확인에 실패하거나 결과가 불확실하면 버튼을 반복해서 누르지 말고 프로젝트 새로고침으로 정식 상태를 대조합니다. 다른 곳에서 먼저 수정했을 때는 기존 입력을 보존한 채 최신 revision을 확인하세요.

Workspace·Wiki 탐색

Workspace Explorer에서 허용된 폴더·파일을 열고, 파일 이름·경로·크기·수정 시각과 미리보기 또는 파일 다운로드를 확인합니다. 표시 한도 초과나 미지원 형식은 빈 문서로 취급하지 않습니다. 권한이 있는 다운로드가 별도로 제공될 수 있습니다.

Wiki Explorer는 문서·검색·3D 그래프 보기를 제공합니다. 검색은 제목·경로 기준이며 상위 20개 결과만 표시될 수 있습니다. 그래프도 안전한 노드/연결 표시 한도가 있어 전체 Wiki의 완전한 그림으로 간주하지 않습니다. 결과나 그래프의 항목을 선택한 뒤 실제 문서 경로·revision이 맞는지 확인합니다. Wiki revision이 바뀌었다는 안내가 나오면 목록을 다시 읽습니다.

파일·다이어그램 미리보기

자료화면에서 확인할 것
Markdown·텍스트제목·문단·표·코드와 안전한 내부 링크를 읽습니다. Markdown의 mermaid 코드 블록은 제한된 수·크기 안에서 격리 렌더링됩니다.
이미지·HTML이미지는 파일 내용을 표시하고, HTML은 격리된 HTML 미리보기와 안전한 소스 보기로 확인합니다. 외부 스크립트 실행이나 원본 페이지 권한 승계를 기대하지 않습니다.
PDF페이지 표시와 이전 페이지·다음 페이지·축소·확대를 사용합니다. 미리보기 한도는 3 MiB·500쪽이고 암호화 PDF는 지원하지 않습니다. 한글 글꼴/문자표 자원이 없으면 실패 안내 후 허용된 다운로드로 확인합니다.
Mermaid.mmd·.mermaid 파일이나 Markdown 코드 블록의 다이어그램을 격리 화면에서 봅니다. 렌더링에 실패하면 안전한 소스 보기로 문법을 확인합니다.

미리보기는 파일을 수정하지 않습니다. 서버가 허용한 콘텐츠·용량·권한 범위 밖의 항목은 표시하지 않습니다.

실패·권한·미지원 상태

로그인이 필요합니다 또는 이 항목을 볼 권한이 없습니다가 보이면 인증과 계정 권한을 확인합니다. 다시 조회로 상태를 갱신하되 실패한 쓰기 요청은 먼저 정식 읽기 결과를 대조합니다. 대시보드의 일부 확인, 프로젝트 연결 불일치, Wiki revision 변경, 파일 미리보기 실패는 각각 별도 상태입니다. 이를 빈 결과나 성공으로 기록하지 않습니다.

이 후보에서 설정·예약·Mattermost 정책·Skills·Tools·Connectors·업데이트를 조작할 때는 해당 Worker의 /console?ui=legacy로 이동합니다. 적용 후 실제 화면과 조작 결과를 촬영해 이 문서의 후보 표시를 갱신해야 합니다.

시작 조건

10월 27일 후보가 정확히 적용된 승인된 시험 Worker, 일반 사용자와 필요한 관리자 계정, 비밀이 없는 Chat/RRA·프로젝트·Workspace/Wiki 샘플 자료를 준비합니다. 적용 전에는 미실행으로 기록합니다.

실행 순서

  1. 로그인 후 /console에서 Console Next가 열리고 최근 세션·프로젝트·대시보드의 실제 제목과 상태를 읽는지 확인합니다.
  2. 새 대화만 만들고 자동 실행이 없는지 확인한 뒤 가상 요청을 명시적으로 전송합니다. 대기 요청의 수정·실행·삭제 확인, 실행 중 취소의 최종 상태를 별도로 기록합니다.
  3. 완료된 RRA 응답에서 일반 대화 초안을 만들되 자동 실행이 없는지 확인하고, RRA 원본 대화의 별도 sessionId와 혼동되지 않는지 확인합니다.
  4. 프로젝트 상세·새 프로젝트/세션·연결 해제와 Dashboard의 정확한 대상 이동을 시험합니다. 결과 불명 변경은 다시 실행하지 않고 새로고침으로 대조합니다.
  5. Workspace Markdown·이미지·HTML·PDF·Mermaid와 Wiki 문서·검색·3D 그래프를 열어 한글 PDF, 안전 소스 보기, 한도/권한 오류를 확인합니다.
  6. 설정·예약 등 기존 기능 링크로 /console?ui=legacy에 이동하고 데스크톱·390px 화면을 각각 촬영합니다.
