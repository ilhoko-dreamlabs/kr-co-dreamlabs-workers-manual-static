최신 화면 재촬영 전이 페이지의 캡처와 클릭 결과는 2026년 10월 1일 worker00 기준입니다. 이후 좌측 탐색과 일부 설정 UI가 바뀌었습니다. 현재 배포의 화면 증거로 사용하지 말고, 실행 검사에서는 최신 메뉴와 실제 결과를 새로 기록하세요. 새 탐색 메뉴 안내

1최종 상태 확인하기

작업 진행중이 사라질 때까지 기다린 뒤 최종 답변과 Worker result 상태를 읽습니다. blocked 또는 failed이면 요청한 일이 완료되지 않았을 수 있습니다.

2문의할 정보 모으기

발생 시각, 작업한 세션, Task 식별자, 오류 메시지를 메모합니다. 비밀번호·토큰·비밀 환경 변수는 전달하지 않습니다.

3재실행 여부 판단하기

외부 서비스에 글을 쓰거나 파일을 바꾼 요청은 실제 처리 여부를 확인한 뒤 다시 실행합니다. 이번 예제는 가상 텍스트 정리만 요청했고, 운영 담당자 확인 후 다시 실행해 정상 결과를 받았습니다.

4다른 워커 요청이 멈춘 경우

승인 대기가 만료됐으면 새 요청을 준비하고 대상을 다시 확인합니다. delivery_uncertain이면 기존 보낸 요청의 전송 상태 복구를 먼저 사용해 대상 History와 대조합니다. 중복을 막기 위해 같은 요청을 새로 보내지 않습니다. blocked/failed이면 양쪽 요청 ID와 원인을 기록합니다.

5스킬이 적용되지 않은 경우

설치 기록, 사용 허용, 로딩 방식, 적용 범위와 요청별 선택 결과를 순서대로 확인합니다. 선택 미리보기와 실제 새 작업 기록을 구분하세요. 범위 밖·비활성·한도 초과 스킬은 선택되지 않을 수 있으며 설치만 반복해서 해결되지 않습니다.

6업데이트 화면이 차단된 경우

현재/대상 할당과 차단 사유, 진행 단계, 보존 요청 대기열을 읽습니다. 자동 할당이나 이미 끝난 할당은 수동 실행할 수 없습니다. 유지보수 중 연결이 끊기면 새로고침 또는 재로그인 후 상태를 읽고, 성공 확인 전 새 업데이트를 다시 요청하지 않습니다.
