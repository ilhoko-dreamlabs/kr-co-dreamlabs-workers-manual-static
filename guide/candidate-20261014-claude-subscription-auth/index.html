무엇이 달라졌나

이전 Worker는 Claude 파일 로그인에 액세스 토큰 만료가 기록되면 갱신 토큰과 네이티브 Claude CLI의 구독 로그인 상태가 남아 있어도 실행 전에 거부할 수 있었습니다. 이 이미지는 갱신 토큰이 있고 네이티브 상태가 로그인됨·Claude 구독·first-party로 확인되면 요청을 CLI로 넘겨 정상 갱신 기회를 줍니다. Worker가 토큰을 직접 갱신하거나 실패한 업무 요청을 자동으로 다시 보내지는 않습니다.

구독용 OAuth 토큰은 종량제 API 키·bearer 자격 증명과 구별합니다. 네이티브 로그아웃, 잘못된 상태, 다른 제공자, API 키·helper 경로 또는 --bare 실행은 구독 준비 완료로 표시하지 않습니다. 다른 Adapter, 특히 Kimi 실행에 Claude 토큰이 전달되지 않도록 경계를 유지합니다. 인증 상태는 실제 설정 홈과 구조화된 네이티브 상태를 기준으로 읽습니다.

구독 계정 사용법

  1. 사용자는 claude-worker가 이번 이미지를 실행 중인지 운영 담당자의 적용 확인을 먼저 받습니다. 콘솔 표시 버전만으로 정확한 이미지를 추정하지 않습니다.
  2. 기존 Claude 구독 파일 로그인을 사용하는 경우, 로그인 파일을 삭제하거나 갱신 토큰을 복사하지 않습니다. 관리자 진단에서 네이티브 로그인됨·구독 제공자와 Worker의 사용 가능 판정을 대조합니다.
  3. 승인된 무해한 시험 요청 한 건을 Claude로 실행하고, 최종 Task 상태와 실제 답변을 확인합니다. 만료된 액세스 토큰이 있는 경우에도 CLI의 갱신 기회를 거쳐 성공했는지는 실제 요청 결과로만 판단합니다.
  4. 실패하면 표시된 최종 오류·시각·Task ID를 기록하고 운영 담당자에게 전달합니다. 같은 요청을 무작정 반복하거나 비밀 토큰을 채팅·캡처에 붙이지 않습니다.

장기 구독 토큰 발급·주입은 사람의 인증과 보호된 비밀 관리가 필요한 별도 운영 절차입니다. 이번 이미지에 토큰을 발급하거나 넣지 않았으며 기존 파일 로그인은 유지합니다.

자격 증명과 기능 경계

구독 준비 상태는 실제 제공자 요청 성공의 보증이 아닙니다. CLI가 갱신·요청을 시도한 뒤 실패하면 그 실패를 최종 결과로 취급합니다. 장기 토큰을 사용할 때에도 종량제 API 키로 조용히 전환하지 않으며, 거부된 장기 토큰을 만료된 파일 로그인으로 자동 대체하지 않습니다. --bare 모드에서는 구독 인증을 허용하지 않습니다.

설정 화면의 환경 변수 비밀값 마스킹은 표시 가림 기능이며 암호화된 비밀 저장소가 아닙니다. 비밀값은 공개 매뉴얼·소스·캡처에 기록하지 않습니다. 선택적 Claude 의미 요약은 기존 파일 로그인 자격 확인 범위에 남아 있으며 장기 토큰 방식은 이번 보정으로 새로 검증되지 않았습니다. 번들 Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2, Node 22.23.3 버전은 앞선 이미지와 같습니다.

확인된 검사

깨끗한 소스에서 전체 개발 검사 455건 통과, Wiki 검증과 최소 안정성 검사가 통과했습니다. 인증 회귀 검사 17개 그룹과 로컬 불변 이미지의 격리 인증 검사가 통과했습니다. 이미지 내부 파일 1,384개의 출처·무결성을 확인했고 네트워크 차단·읽기 전용·비루트 환경에서 구성요소 버전과 이전 기능 보존을 점검했습니다.

별도 적용 후 읽기에서 claude-worker의 정확한 실행 이미지·정상 건강·인증 준비 상태는 확인했습니다. 이것은 운영 로그인 파일의 실제 갱신 성공이나 Claude 모델 응답을 입증하지 않습니다. 장기 토큰은 발급·주입하지 않았고, 실제 모델 요청과 재시작 보존 시험은 아직 없습니다.

적용 후 재현 검사

  1. claude-worker의 정확한 실행 이미지·건강·재시작 상태를 다시 읽고, 기동 정규화된 상태 파일과 보존된 설정·마운트의 판정을 비공개 운영 기록에서 확인합니다.
  2. 비밀값을 출력하지 않는 진단으로 실제 설정 홈과 네이티브 로그인 상태가 구독·first-party·로그인됨인지 확인합니다. 액세스 만료와 갱신 토큰 존재는 구분하고, 갱신 토큰이 없는 만료 파일은 준비 완료로 판정하지 않습니다.
  3. 사람이 승인한 무해한 Claude 모델 요청 한 건을 실행해 최종 상태와 답변을 확인합니다. 네이티브 갱신의 성공 여부는 이 실제 결과로 판정하며, 실패하면 중복 실행 없이 원인을 기록합니다.
  4. 격리 시험에서는 네이티브 로그아웃·잘못된 상태·다른 제공자·API 키 경로·--bare의 구독 인증 거부와 Kimi 등 다른 Adapter로 토큰이 넘어가지 않는지를 확인합니다. 운영 자격 증명을 변형해 시험하지 않습니다.
  5. 장기 토큰 전환을 별도로 승인받았다면 보호된 비밀 주입과 재시작 보존, 만료·교체 계획을 검증합니다. 이 단계는 이번 적용의 완료 결과가 아닙니다.

각 항목에 워커 이름·이미지 식별·시각·Task 결과를 남기고, 비밀값은 기록하지 않습니다. 현재 이미지·건강·인증 준비 읽기만 확인됐으며, 실제 모델 요청과 갱신 성공은 미검증입니다.
