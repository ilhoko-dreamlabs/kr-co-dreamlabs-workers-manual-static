상태확인 의미
로컬 검증정확한 개발 소스와 격리 테스트에서 기대 동작을 확인했습니다. 실제 제공자와 운영 계정 결과는 별도입니다.
로컬 이미지해당 소스를 패키지로 빌드하고 식별했습니다. Registry·서버·워커 단계로 자동 진행되지 않습니다.
공급·제안관리자가 사용할 수 있는 후보가 준비된 단계입니다. 워커 실행 이미지는 바뀌지 않았을 수 있습니다.
지정 워커 적용정확한 실행 이미지·건강·보존 자료·실제 기능을 대상별로 다시 확인한 경우에만 사용합니다.

11월 20일 Console Next 기능·복구 이미지와 그 다음 Hono 패치 이미지는 서로 다른 로컬 후보입니다. 최신 업데이트 v4 소스는 두 이미지 이후 작업이므로 어떤 로컬 이미지에도 포함된 것으로 표시하지 않습니다.

370개 기능 추적 현황

Console Next의 추적 항목 370개를 항목별 소스·검사로 대조한 결과는 로컬 검증 358개, 부분 구현 1개, 정책·소유자·외부 제품 조건으로 차단 11개입니다. 이 수치는 배포 완료율이 아닙니다. 실제 계정·서비스·Portable·운영 워커 수용은 별도입니다.

부분 구현 항목은 PLAN-12 Worker 간 outbound RRA 첨부 전달입니다. 현재 첫 요청과 후속 요청의 대상 전송에는 첨부 선택·전달이 연결되지 않았습니다. 수신 RRA의 첨부 처리나 일반 Chat의 파일 기능을 이 항목의 완료로 보지 않습니다. 사용자 승인·범위·자료 해시·대상 수령 증거가 포함된 별도 계약과 구현이 필요합니다. 정책 차단 항목에는 Worker Trust의 광범위한 권한 모델, 외부 채널·호스트 운영 기능, 사용자 보고·Portable 도입 범위 등이 있습니다.

일반 사용자 화면 변화

Chat의 세션·후속 요청·대기열·첨부, 프로젝트·Wiki·작업공간 파일, 검색·공개 실행 기록, 승인 요청·진행 상태와 대시보드가 로컬 소스에서 확장되었습니다. 버전별 기능이 현재 운영 워커에서 보이는지 판단하려면 정확한 실행 이미지를 확인하고 각 화면의 직접 테스트 절차를 수행해야 합니다. 기존 Console Next 탐색과 기능별 안내는 10월 후보 기준 설명이므로, 최신 소스의 세부 조작은 실제 적용 이미지에서 재촬영·재검증해야 합니다.

관리자 설정 변화

새 Console의 연결 상세가 네 곳뿐이던 C10 이후, 환경·Worker Base·런타임·어댑터 인증, 연결·RRA 대상, 스킬·업데이트·시스템·예약·공개 페이지 등의 화면과 API가 단계적으로 연결됐습니다. 현재 설정 상세, 연결 관리, 스킬 관리에 관리자·일반 사용자 경계와 저장 후 재조회 방법을 나눠 적었습니다. 관리 화면의 표시만으로 실제 외부 계정 인증, 모델 요청이나 새 워커 적용을 통과로 판정하지 않습니다.

RRA·연결 경계

공개 RRA HTTP v1 규약의 요청·결과·세션 이어가기 방식은 이 소스 변경으로 바뀐 것으로 확인되지 않았습니다. 새 RRA 대상 Worker 관리자 화면은 서버가 소유하는 대상 연결을 등록·수정·삭제하는 설정 경계입니다. 대상이 저장되어도 사용자별 요청 승인, 대상 워커의 독립 입장 검사, 멱등성과 결과 대조는 계속 필요합니다. 후속 대화 고정 URL은 기존 계약을 설명하며, PLAN-12의 미구현 첨부 전달을 지원한다고 읽으면 안 됩니다.

공개 프로필 페이지

SITE-01~06은 로컬 검증됐습니다. 관리자는 프로필 이름·설명·이미지와 공개 페이지의 고정 필드를 편집하고 미리보기 → 변경 확인 → 공개 결과 재조회를 분리합니다. Chat에서 공개 작업을 도울 때도 미리보기와 별도 확인을 거쳐야 합니다. 미리보기는 공개가 아니고, 이미 공개된 페이지를 되돌리는 작업도 별도입니다. 익명 페이지와 관리자 편집 권한, 원본 자료·계정 경계를 실제 도메인에서 다시 확인해야 하며 이 후보의 실제 운영 화면은 아직 촬영되지 않았습니다.

업데이트·자료 복구 개발

11월 20일 로컬 이미지는 자료 복구 검사를 포함하지만, 운영 worker0에 새 이미지를 적용하지 않았습니다. 기존 RRA 자료 형식과 후보 형식 간 이전 이미지 복귀는 독립 복구 계획이 필요합니다. 그 뒤 개발 브랜치에는 호환성 평가, 수동 동의·증거 기반 요청을 위한 업데이트 v4 계약/클라이언트/Host 구성 요소가 추가됐습니다. 현재는 소스 단계이며 운영 진입, Manager v4, 실제 증거 발급·독립 보관·UI가 연결되지 않았습니다. 최신 Host 통합 집중 검사 29건·클라이언트 20건·계약 30건은 통과했고, 첫 전체 검사는 기존 세션 검색 브라우저 타임아웃 1건으로 실패했습니다. 단독 재실행 통과는 전체 검사 통과로 바꾸어 쓰지 않습니다.

따라서 사용자가 Console의 기존 전체 Worker 릴리스를 새 v4 흐름으로 해석하거나 수동 업데이트를 진행해서는 안 됩니다. CLI 개별 업데이트도 별도 버튼이 아니라 전체 Worker 릴리스 경계를 따릅니다.

Chrome 확장 게이트웨이 설계

11월 20일 별도 작업 트리에는 Chrome 확장 게이트웨이의 설계와 격리 로컬 프로토타입이 있습니다. 실제 Worker 연결, HTTPS 브리지, Chrome 설치·운영 배포는 아직 없습니다. 확장 패널의 로컬 사용자 동의와 서버의 요청 정책은 서로 다른 경계로 설계 중이며, 이를 현재 Worker 기능이나 RRA 공개 규약으로 표시하지 않습니다.

계획대로 구현됐는지 직접 판정

  1. 먼저 화면의 워커 이름과 정확한 실행 이미지·시각을 기록합니다. 소스만 있는 기능은 미실행으로 남깁니다.
  2. 관리자·일반 사용자로 새 설정·연결·스킬의 접근 차이를 비교하고, 가능한 곳에서는 저장 응답 뒤 canonical 재조회를 수행합니다.
  3. Chat·RRA의 같은 세션 후속 요청을 가상 자료로 시험하고, Worker 간 첨부 전달은 지원 항목으로 가정하지 않습니다.
  4. 결과 불명·권한 상실·충돌에서 보호 정보 제거와 중복 쓰기 방지를 확인합니다.
  5. 실제 이미지가 적용된 경우에만 데스크톱·모바일 화면과 보존 자료를 촬영·대조해 통과/실패/차단/미실행을 기록합니다. 390px 로컬 합성 화면에서는 설정 설명과 연결 ID 일부가 오른쪽으로 잘려 모바일 레이아웃 수정·재검증이 필요합니다.

화면 캡처 상태

화면 미촬영 · 11월 20일 후보의 운영 Worker 화면은 아직 촬영하지 않았습니다. 이 페이지에 포함할 수 있는 로컬 합성 화면은 소스 UI 배치 참고용이며 운영 수용 증거가 아닙니다.
