시스템 이벤트: 대화 요청과 별도로 받기

이 이미지에는 같은 워커 서버의 독립된 시스템 이벤트 수신 경로가 포함됩니다. 등록된 발행자의 인증·권한과 대상 워커를 검사한 뒤 접수 기록, 처리 결과, 중복 수신 방지와 재시작 후 복구 기록을 남기도록 구현했습니다. 접수 성공과 실제 스킬 변경 성공은 별도 상태입니다.

시스템 이벤트는 워커 간 RRA 요청과 다른 경로입니다. RRA 대화·키·History·모델 실행 슬롯으로 처리하지 않으며, 이벤트 한 건마다 채팅 대화나 승인 팝업을 만들지 않습니다. 이 이미지만 설치해도 CI 알림이 자동으로 시작되는 것은 아닙니다. 발행자 등록, 네트워크 신뢰와 CI 전달 설정은 운영 통합 단계에서 별도로 확인해야 합니다.

관리자 설정과 결과 확인

관리자는 Settings → System → System events에서 수신 활성화, 발행자 연결과 최근 접수·결과를 확인합니다. 10월 13일 worker0의 실제 화면을 읽어 handler ready · 수신 꺼짐 · 발행자 0명을 확인했습니다. 준비 상태는 이벤트 전달 성공이나 자동업데이트 실행을 뜻하지 않습니다. 한국어·영어 화면이 준비돼 있고, 기존 설정 갱신 체계를 통해 보이는 화면만 새 상태를 반영합니다. 저장 성공, 접수, 실제 처리 결과를 한 가지 성공으로 합쳐 보지 마세요. 발행자 자격 증명과 상세 운영 값은 내부 운영 문서에서 관리합니다.

현재 외부 HTTPS capabilities 확인은 신뢰할 수 있는 프록시 구성이 없어 EVENT_SECURE_TRANSPORT_REQUIRED로 거부됩니다. 보안 경로가 준비되기 전에는 수신 활성화나 발행자 등록·전송 시험을 완료로 표시할 수 없습니다. 관리자 콘솔에서 요청할 때만 불러오는 이벤트 처리 안내 스킬과 읽기 전용 상태 도구도 포함됩니다. 안내 스킬이 이벤트를 직접 수신하거나 설정을 바꾸지는 않습니다. 일반 사용자, RRA·예약 작업 또는 외부 발행자에게 관리자 조회 권한이 생기는 기능이 아닙니다.

이미 설치된 Registry 스킬의 선택적 자동업데이트

Settings → Skills에서는 전체 자동업데이트 허용과 설치된 각 스킬의 허용을 따로 설정합니다. 두 설정이 모두 켜져야 해당 스킬의 자동 변경이 가능합니다. 기존 설치 기록은 기본 꺼짐이며, 새로 게시된 스킬을 자동 설치하거나 사용 중지된 스킬을 자동 활성화하지 않습니다. 설치와 실제 작업의 스킬 사용 허용은 계속 별개입니다.

호환되는 카탈로그·버전·패키지 무결성과 현재 설치 원본을 확인하고, 로컬에서 편집된 내용이나 실행 중·대기 중인 작업과 충돌하면 교체를 보류합니다. 승인된 경우에도 기존 패키지를 보호하면서 원본 패키지 교체와 실행 어댑터 반영 결과를 따로 기록합니다. 화면의 확인은 현재 카탈로그의 새 버전 유무를 다시 보는 동작이고, 자동 허용이 꺼져 있으면 비교 결과만 보여 주며 파일을 교체하지 않아야 합니다. 수신 경로가 꺼져 있어도 로컬 확인은 별도로 동작하도록 설계했습니다.

관리자는 설치 버전·사용 가능한 버전·마지막 확인·보류/실패 이유를 읽고, 실제 버전 변경과 어댑터 적용 결과를 다시 조회해야 합니다. 지원하지 않는 로컬·네이티브·번들 스킬 행에는 자동 허용 대신 이유가 표시됩니다. 수동 스킬 설치 사용법은 그대로 유효합니다. worker0에서는 자동 허용·단일 스킬 교체·어댑터 결과의 운영 시험을 아직 수행하지 않았으므로 소스 동작을 운영 통과로 표시하지 않습니다.

같은 이미지에 포함된 다른 개선

  • Git 스킬 다운로드: 내려받을 때 주변 Git 훅·필터·전역 설정의 개입을 차단해 카탈로그 원본 바이트가 바뀌지 않도록 보완했습니다. 사설 Git의 CA·프록시 연결은 운영망에서 별도 검사가 필요합니다.
  • 전체 워커 자동 업데이트 일정: Manager 채널·정책 저장, 동일 일정의 중복 실행 방지, 워커가 바쁠 때 건너뛰거나 차단한 이유의 피드백을 보완했습니다. 이는 설치 스킬 자동업데이트와 다른 기능이며, 이 이미지 빌드가 운영 일정을 활성화하거나 Manager 설정을 바꾸지 않았습니다.

확인된 검사와 제한

정확한 깨끗한 소스에서 집계 검증은 448건 통과·실패 0·차단 0입니다. 한국어·영어 UI와 헤드리스 브라우저 구성 요소 검사를 포함했습니다. 로컬 이미지 안의 애플리케이션 파일 1,361개와 소스 유래 식별을 대조했고, 읽기 전용·네트워크 차단 격리 검사에서 기본 이벤트 수신 및 스킬 자동업데이트가 모두 꺼져 있음을 확인했습니다. 원격 Registry의 불변 이미지 식별과 서버 배치 이미지를 같은 빌드로 재검증했습니다. 번들 CLI는 Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2로 앞선 이미지와 같습니다.

worker0의 새 실행 이미지·건강 상태·업데이트 성공과 기존 대화·프로젝트·인증·Wiki·Skills의 존재를 확인했습니다. 저장 내용 전체의 변경 전후 동일성, 실제 CI 발행자 전달, 사설 Git 연결, 외부 모델, 단일 스킬 자동업데이트와 어댑터 결과는 검증하지 않았습니다. 첫 worker00 CI 요청은 작업 대기 시간 만료로 실패했습니다. 재시도는 원격 실행을 마쳤지만 GitLab Connector 기록 검증 오류로 CI 구현이 차단됐습니다. worker00 운영 Wiki 기록은 확인했으나 CI 코드·게시 작업의 commit/push와 실제 이벤트 전송은 0건입니다. 원격 요청의 완료를 CI 연동 성공으로 해석하지 마세요. 애플리케이션 생산 의존성 감사 0건은 OS·CLI 전체 취약점 검사 결과가 아닙니다.

운영 재현 검사

  1. worker0의 정확한 실행 이미지·건강 상태와 보존된 대화·프로젝트 수를 새 시각에 다시 읽습니다. 수신 꺼짐·발행자 0명과 스킬 자동 허용의 실제 설정을 각각 확인합니다.
  2. 관리자 계정으로 Settings → System → System events를 열어 handler 상태와 수신/발행자/접수 결과를 데스크톱·좁은 화면에서 촬영합니다. 신뢰 프록시와 HTTPS capabilities 차단을 해결하기 전에는 외부 이벤트 시험을 통과로 표시하지 않습니다.
  3. 승인된 시험 환경에서만 발행자 자격과 안전한 합성 이벤트를 준비합니다. 잘못된 인증·대상 거부, 접수와 최종 처리, 중복 재전송과 재시작 뒤 기록을 각각 확인합니다. RRA 대화가 만들어지지 않아야 합니다.
  4. Settings → Skills에서 승인된 시험용 이미 설치된 Registry 스킬을 정합니다. 전체 또는 개별 허용이 꺼진 상태에서는 확인만 하고 교체하지 않는지 살핍니다. 양쪽 허용 뒤 호환 새 버전의 설치 결과와 실제 어댑터 반영을 각각 읽습니다.
  5. 미설치·사용 중지·로컬 수정·작업 중·호환 불가 사례는 별도 시험 스킬로 확인합니다. 자동 설치·자동 활성화·충돌 중 교체가 발생하지 않아야 합니다. 마지막에 시험 정책과 발행자 설정을 복원합니다.
  6. CI 발행자 통합·전체 워커 일정·사설 Git 연결은 각각 별도 운영 시험으로 판정합니다. worker00 Wiki 작성이나 원격 요청 완료만으로 CI 알림 전달을 통과로 표시하지 않습니다.
