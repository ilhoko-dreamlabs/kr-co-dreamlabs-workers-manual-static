시스템 이벤트: 대화 요청과 별도로 받기

후보 이미지에는 같은 워커 서버의 독립된 시스템 이벤트 수신 경로가 포함됩니다. 등록된 발행자의 인증·권한과 대상 워커를 검사한 뒤 접수 기록, 처리 결과, 중복 수신 방지와 재시작 후 복구 기록을 남기도록 구현했습니다. 접수 성공과 실제 스킬 변경 성공은 별도 상태입니다.

시스템 이벤트는 워커 간 RRA 요청과 다른 경로입니다. RRA 대화·키·History·모델 실행 슬롯으로 처리하지 않으며, 이벤트 한 건마다 채팅 대화나 승인 팝업을 만들지 않습니다. 이 이미지만 설치해도 CI 알림이 자동으로 시작되는 것은 아닙니다. 발행자 등록, 네트워크 신뢰와 CI 전달 설정은 운영 통합 단계에서 별도로 확인해야 합니다.

관리자 설정과 결과 확인

관리자는 후보가 실제 적용된 뒤 Settings → System → Events에서 수신 활성화, 발행자 연결과 최근 접수·결과를 확인할 수 있습니다. 한국어·영어 화면이 준비돼 있고, 기존 설정 갱신 체계를 통해 보이는 화면만 새 상태를 반영합니다. 저장 성공, 접수, 실제 처리 결과를 한 가지 성공으로 합쳐 보지 마세요. 발행자 자격 증명과 상세 운영 값은 공개 매뉴얼에 싣지 않고 내부 운영 문서에서 관리합니다.

관리자 콘솔에서 요청할 때만 불러오는 이벤트 처리 안내 스킬과 읽기 전용 상태 도구도 포함됩니다. 안내 스킬이 이벤트를 직접 수신하거나 설정을 바꾸지는 않습니다. 일반 사용자, RRA·예약 작업 또는 외부 발행자에게 관리자 조회 권한이 생기는 기능이 아닙니다.

이미 설치된 Registry 스킬의 선택적 자동업데이트

후보의 Settings → Skills에서는 전체 자동업데이트 허용과 설치된 각 스킬의 허용을 따로 설정합니다. 두 설정이 모두 켜져야 해당 스킬의 자동 변경이 가능합니다. 기존 설치 기록은 기본 꺼짐이며, 새로 게시된 스킬을 자동 설치하거나 사용 중지된 스킬을 자동 활성화하지 않습니다. 설치와 실제 작업의 스킬 사용 허용은 계속 별개입니다.

호환되는 카탈로그·버전·패키지 무결성과 현재 설치 원본을 확인하고, 로컬에서 편집된 내용이나 실행 중·대기 중인 작업과 충돌하면 교체를 보류합니다. 승인된 경우에도 기존 패키지를 보호하면서 원본 패키지 교체와 실행 어댑터 반영 결과를 따로 기록합니다. 화면의 확인은 현재 카탈로그의 새 버전 유무를 다시 보는 동작이고, 자동 허용이 꺼져 있으면 비교 결과만 보여 주며 파일을 교체하지 않아야 합니다. 수신 경로가 꺼져 있어도 로컬 확인은 별도로 동작하도록 설계했습니다.

관리자는 설치 버전·사용 가능한 버전·마지막 확인·보류/실패 이유를 읽고, 실제 버전 변경과 어댑터 적용 결과를 다시 조회해야 합니다. 지원하지 않는 로컬·네이티브·번들 스킬 행에는 자동 허용 대신 이유가 표시됩니다. 수동 스킬 설치 사용법은 그대로 유효하지만, 이 자동 기능은 정확한 이미지 적용 전까지 현재 워커의 메뉴로 안내하지 않습니다.

같은 이미지에 포함된 다른 개선

  • Git 스킬 다운로드: 내려받을 때 주변 Git 훅·필터·전역 설정의 개입을 차단해 카탈로그 원본 바이트가 바뀌지 않도록 보완했습니다. 사설 Git의 CA·프록시 연결은 운영망에서 별도 검사가 필요합니다.
  • 전체 워커 자동 업데이트 일정: Manager 채널·정책 저장, 동일 일정의 중복 실행 방지, 워커가 바쁠 때 건너뛰거나 차단한 이유의 피드백을 보완했습니다. 이는 설치 스킬 자동업데이트와 다른 기능이며, 이 이미지 빌드가 운영 일정을 활성화하거나 Manager 설정을 바꾸지 않았습니다.

확인된 검사와 제한

정확한 깨끗한 소스에서 집계 검증은 448건 통과·실패 0·차단 0입니다. 한국어·영어 UI와 헤드리스 브라우저 구성 요소 검사를 포함했습니다. 로컬 이미지 안의 애플리케이션 파일 1,361개와 소스 유래 식별을 대조했고, 읽기 전용·네트워크 차단 격리 검사에서 기본 이벤트 수신 및 스킬 자동업데이트가 모두 꺼져 있음을 확인했습니다. 원격 Registry의 불변 이미지 식별과 서버 배치 이미지를 같은 빌드로 재검증했습니다. 번들 CLI는 Codex 0.162.0, Claude 2.1.183, Kimi 0.29.2로 앞선 이미지와 같습니다.

공급 검사는 운영 워커의 새 기능 화면, 실제 CI 발행자 전달, 사설 Git 연결, 외부 모델 또는 지정 워커 기능 수용을 대신하지 않습니다. worker00의 CI 연동 준비 요청은 접수됐지만 작업 대기 시간 만료로 실행 전에 실패했고, CI 구성이나 Wiki 변경은 이 요청에서 이뤄지지 않았습니다. 애플리케이션 생산 의존성 감사 0건은 OS·CLI 전체 취약점 검사 결과가 아닙니다. 새 이미지의 데스크톱·모바일 캡처도 아직 촬영하지 않았습니다.

적용 후 재현 검사

  1. 운영 담당자가 지정 워커의 실행 이미지·건강 상태와 이 후보의 정확한 내부 식별을 대조하고, 기본 이벤트 수신·자동 허용이 꺼져 있는지 읽습니다.
  2. 승인된 시험 환경에서 관리자 계정으로 Settings → System → Events를 열어 화면, 발행자 등록 결과와 최근 접수/처리 결과를 확인합니다. 잘못된 인증·대상은 거부돼야 하며 RRA 세션과 기록에는 이벤트 대화가 생기지 않아야 합니다.
  3. 시험 발행자가 안전한 합성 이벤트 한 건을 보내면 접수와 최종 결과를 따로 기록합니다. 같은 이벤트를 다시 보내도 스킬 교체가 중복되지 않는지, 워커 재시작 뒤에도 기존 접수·결과를 다시 읽을 수 있는지 확인합니다.
  4. Settings → Skills에서 승인된 시험용 이미 설치된 Registry 스킬을 정합니다. 전체 또는 개별 허용이 꺼진 상태에서는 확인만 하고 교체하지 않는지 살핍니다. 양쪽 허용 뒤 호환 새 버전의 설치 결과와 실제 어댑터 반영을 각각 읽습니다.
  5. 미설치·사용 중지·로컬 수정·작업 중·호환 불가 사례는 별도 시험 스킬로 확인합니다. 자동 설치·자동 활성화·충돌 중 교체가 발생하지 않아야 합니다. 마지막에 시험 정책과 발행자 설정을 복원합니다.
  6. 전체 워커 업데이트의 일정 저장·중복 실행 방지·바쁨 피드백과 사설 Git 연결은 별도 운영 시험에서 판정합니다. CI 발행자 통합이 완료되기 전에는 알림 전달을 통과로 표시하지 않습니다.

실제 화면 캡처 계획

후보 화면 미촬영입니다. 현재 확보한 업데이트 준비 화면은 직전 이미지로 실행 중인 worker0의 대상 할당 화면이며, 새 시스템 이벤트·스킬 자동업데이트 UI가 아닙니다. 내부 이미지 주소와 식별자가 보여 공개 캡처로 싣지 않았습니다. 지정 워커에 이 이미지가 적용되고 관리자 시험이 허용되면 데스크톱과 좁은 화면에서 시스템 이벤트 설정·최근 접수/결과, 스킬 자동 허용의 전체/개별 상태·버전·보류/실패 결과를 새로 촬영합니다. 워커 이름·이미지·촬영 시각·표시 언어와 조작 결과를 함께 기록하고, 계정·토큰·발행자 키는 가립니다. 앞선 버전의 캡처는 이 후보의 실제 화면으로 재사용하지 않습니다.

실행 순서

  1. 빌드, Registry, 서버 배치, 워커 제안, 실제 적용과 CI 통합을 각각 기록합니다. 적용 전 화면·기능 검사는 미실행으로 둡니다.
  2. 적용 후 이벤트 수신과 전체/개별 스킬 자동 허용이 기본 꺼짐인지 관리자 화면에서 읽고 데스크톱·좁은 화면을 촬영합니다.
  3. 시험 이벤트의 접수와 처리 결과, 잘못된 인증·대상 거부, 같은 이벤트 재전송의 중복 방지와 재시작 뒤 기록 복구를 각각 확인합니다. RRA 대화가 만들어지지 않아야 합니다.
  4. 이미 설치된 시험 Registry 스킬에서 자동 허용 꺼짐 시 비교만 되는지, 양쪽 허용 시 호환 버전의 원본 교체와 어댑터 적용이 각각 성공하는지 확인합니다.
  5. 미설치·사용 중지·로컬 수정·작업 중·호환 불가 사례가 자동 설치·활성화·교체되지 않는지 기록하고 시험 정책을 복원합니다. CI 통합·사설 Git·전체 워커 일정은 별도 운영 시험으로 판정합니다.

통과 기준

이미지 공급·제안·버튼 활성만으로 운영 적용이나 화면·기능 통과를 주장하지 않습니다. 적용 뒤에도 접수/처리, 패키지/어댑터, 스킬 자동업데이트/전체 워커 업데이트를 각각 분리해 판정합니다.

남길 증거

시험 워커·정확한 내부 이미지·적용/검사 시각, 정책 시작/복원값, 시험 이벤트 접수·결과 ID, 스킬 설치·대상 버전과 보류 이유, 데스크톱/모바일 캡처 및 미실행 항목을 기록합니다. 공개 자료에서는 비밀값과 내부 이미지 식별을 제외합니다.
