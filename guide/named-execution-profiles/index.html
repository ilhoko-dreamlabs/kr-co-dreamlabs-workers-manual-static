후보 Registry·서버 배치·제안 확인 / 지정 워커 적용·새 UI 미확인확인일 2026.10.22읽기·검사 약 5분

누가 무엇을 할 수 있나

관리자는 프로필 이름·설명과 어댑터별 모델·추론 강도·속도를 관리하고 Worker 기본값 또는 RRA Key·Mattermost 채널·예약의 연결을 정합니다. 일반 사용자는 허용된 Console 대화에서 사용할 수 있는 프로필을 고르고 미리보기를 볼 수 있지만 관리 설정을 바꾸지 않습니다. 프로필 선택은 도구·자료 접근 권한을 추가하지 않습니다.

프로필은 현재 활성 어댑터를 전환하는 기능이 아닙니다. 여러 어댑터의 매핑을 저장해도 실행 시에는 그 Worker의 단일 활성 어댑터에 해당하는 매핑만 검증합니다.

관리자: 이름 붙인 프로필 추가·수정

  1. 설정 → 런타임 → 실행 프로필 → 설정을 열고 현재 Worker 기본값과 등록된 프로필을 확인합니다.
  2. 프로필 추가에서 업무를 구분할 이름과 설명을 입력합니다. 어댑터 매핑의 모델, 추론 강도, 속도를 각각 고릅니다. 어댑터 기본과 속도의 표준은 서로 다른 선택입니다.
  3. 지원 표시가 지원 확인 · 접수 시 재검증인지 확인합니다. 미지원이나 미검증은 저장돼도 실제 실행을 허용한다는 뜻이 아닙니다. 속도 선택에는 제공자 비용이 따를 수 있습니다.
  4. 저장 후 목록을 다시 읽어 이름·매핑과 Worker 기본값을 대조합니다. 수정은 새 요청에, 복제는 새 프로필에 적용됩니다. 이미 접수된 요청은 원래 설정을 유지합니다.
  5. 삭제 전 사용처·삭제 영향 확인으로 직접 연결과 확인 불가 연결을 읽습니다. 필요하면 삭제 시 대체 프로필을 고르거나 상속으로 돌린 뒤 삭제를 확인합니다. 기존 결과 카드의 당시 프로필 기록은 새 이름으로 바꾸지 않습니다.

다른 관리자의 저장으로 revision이 바뀌었다면 최신 값을 다시 읽고 초안과 비교합니다. 미확인 연결이 있으면 삭제 효과를 단정하지 않습니다.

이번 요청에 적용되는 상속 순서

요청 출처먼저 적용되는 선택그 다음
Console 대화이번 요청 프로필세션 기본 프로필 → Worker 기본값
RRA 요청인증된 API Key의 설정Worker 기본값
Mattermost서버가 확인한 채널 설정Worker 기본값
예약·지금 실행예약 설정Worker 기본값

상속은 프로필 전체를 고릅니다.부모의 모델과 다른 프로필의 추론·속도를 섞지 않습니다. Worker 기본값 상속은 현재 기본 프로필을 따르며, 어댑터 기본은 제공자의 기본 선택으로 돌아가는 명시적 설정입니다. 설정이 바뀌어도 이미 접수된 대기·실행 요청의 고정 스냅샷은 바뀌지 않습니다.

사용자: 대화에서 프로필 선택·미리보기

  1. 새 대화 또는 기존 대화의 입력란에서 이번 요청 프로필을 엽니다. 세션 설정 상속을 유지하거나 사용 가능한 프로필 하나를 고릅니다.
  2. 실행 설정 미리보기를 눌러 현재 어댑터·모델·추론·속도와 지원 상태를 읽습니다. 미리보기는 모델을 실행하거나 실제 계정 권한을 검증하지 않습니다.
  3. 안전한 시험 요청을 보내고 최종 카드의 접힌 실행 프로필을 열어 접수 시 고정된 이름·어댑터·모델·추론·속도를 확인합니다. 대기 중 프로필을 수정해도 이 카드가 새 값으로 바뀌지 않아야 합니다.

세션을 바꾸거나 선택·목록을 새로고침하면 이전 미리보기를 현재 값으로 사용하지 않습니다. 오래된 결과에 접수 설정이 없으면 저장되어 있지 않습니다로 표시하고 현재 프로필을 과거 실행 설정으로 추정하지 않습니다.

관리자: RRA Key·채널·예약에 연결하기

RRA Key 상세, Mattermost 채널 설정, 예약 편집에서 각 항목의 실행 프로필을 선택하거나 Worker 기본값 상속을 고릅니다. 저장 후 같은 항목을 다시 열어 선택을 대조하고, 새 요청의 접수 기록과 실제 최종 상태를 확인합니다. RRA의 공개 POST /api/v1/requests 본문은 이전 규약 그대로이며 profileId, 모델·추론·속도 override를 받지 않습니다. 요청 본문의 주장은 Key 설정을 바꿀 수 없습니다. RRA v1 연동 규약도 함께 보세요.

Mattermost 연결은 표시 이름이 아니라 서버가 보유한 채널 식별자를 기준으로 합니다. 예약의 프로필은 예약 정의에서 선택하지만 실행 설정은 각 실행의 접수 순간에 고정됩니다. 연결 저장만으로 이전 메시지나 예약 실행을 다시 수행하지 않습니다.

관리자: 예약을 한 번만 지금 실행

  1. 왼쪽 예약에서 시험 예약을 선택하고 이름·저장된 프롬프트·실행 프로필·다음 예약 시각을 먼저 기록합니다.
  2. 지금 실행을 한 번 누릅니다. 요청 중…은 접수 과정이고, 접수되었습니다는 아직 완료가 아닙니다. 같은 예약의 정기 실행과 실행 레인을 공유합니다.
  3. 실행 상태 확인과 실행 이력에서 접수 → 실행 시작 → 완료/실패를 구분합니다. 완료 뒤에도 다음 예약 시각이 그대로인지 확인합니다. 일시 중지된 반복 예약도 명시적인 수동 실행은 가능합니다.
  4. 응답을 받지 못했으면 화면의 동일 요청 다시 확인으로 원래 작업을 조회합니다. 임의로 두 번째 새 실행을 만들지 않습니다. 실패가 최종 상태면 원인을 확인하고 새 실행 여부를 별도로 결정합니다.

실행 중 재시작 뒤 상태가 오래 실행을 시작했습니다에 머물면 결과 확인이 필요합니다. Worker는 불확실한 작업을 자동 재실행하지 않습니다. 설정 revision 충돌이면 현재 설정을 새로 읽은 뒤 다시 판단하세요. 지금 실행은 정기 예약의 다음 시각을 바꾸지 않습니다.

결과 카드와 오류 읽기

결과 카드·예약 실행 이력의 실행 프로필 부분은 접수 당시 설정이며 제공자가 실제로 처리한 모델·과금의 독립 증명은 아닙니다. 최종 업무 성공은 Task 상태와 답변 내용으로 따로 판정합니다.

상태·코드확인할 일
미지원·미검증 옵션저장된 매핑과 활성 어댑터의 현재 capability를 확인합니다. 임의 기본 모델로 바꿔 실행하지 않습니다.
EXECUTION_PROFILE_MAPPING_MISSING현재 활성 어댑터의 매핑을 관리자에게 확인합니다.
EXECUTION_PROFILE_REVISION_CONFLICT다른 저장 결과를 재조회하고 변경 내용을 비교합니다.
EXECUTION_PROFILE_CALLER_OVERRIDE_FORBIDDENRRA 호출 본문에서 프로필·모델 override를 제거하고 서버 Key 설정을 확인합니다.
상태 확인 불가·재시작 뒤 결과 불명기존 요청·예약 실행 ID와 이력을 대조합니다. 이미 일어난 외부 효과를 먼저 확인하고 중복 실행하지 않습니다.

Claude 사용자 정의 프로필의 이전 legacy 경로와 검증되지 않은 Fast 옵션은 이 후보에서 지원되지 않습니다. 예전 이미지로 되돌리는 복구는 지원 경로가 아니므로 관리자에게 후속 수정 이미지와 자료 보존 상태를 확인받으세요.

아직 필요한 실제 화면

새 후보 화면은 미촬영입니다. 관리자 프로필 목록·편집/복제·사용처/삭제, 일반 사용자 요청 선택·미리보기·결과 카드, RRA Key·Mattermost 채널·예약 상속, 예약 지금 실행의 접수/완료/결과 불명 상태를 데스크톱·모바일에서 실제 UI로 촬영해야 합니다. 운영 화면은 지정 워커 적용을 확인한 뒤 별도로 확보합니다. 이전 버전의 실행 옵션 사진을 이 후보의 현재 화면처럼 사용하지 않습니다.

시작 조건

후보 이미지가 지정된 시험 Worker에 실제 적용된 뒤 관리자·일반 사용자 계정, 안전한 시험 프로필·예약·RRA Key·채널을 준비합니다. 적용 전에는 화면 위치만 소스 기준으로 검토합니다.

실행 순서

  1. 설정 → 런타임 → 실행 프로필에서 프로필을 추가·저장·재조회·복제하고 사용처·삭제 영향을 확인합니다.
  2. Console 이번 요청과 세션 설정 상속으로 서로 다른 요청을 접수해 미리보기와 결과 카드의 접수 시 설정을 비교합니다.
  3. RRA Key·Mattermost 채널·예약의 프로필 연결을 저장하고 새 요청에서 Worker 기본값 상속과 연결 선택을 비교합니다.
  4. 예약 지금 실행을 한 번 제출해 상태·결과·다음 예약 시각 불변을 확인하고 응답 손실 시 동일 요청 상태를 조회합니다.
  5. 미지원·미검증 옵션, RRA 본문 override, revision 충돌과 과거 스냅샷 없는 기록의 표시를 확인합니다.

통과 기준

역할별 권한과 전체 프로필 상속 순서가 맞고, 이미 접수한 실행 설정은 뒤늦은 수정으로 바뀌지 않습니다. RRA caller override는 거부되고 예약 수동 실행은 중복 없이 종료 상태를 확인할 수 있습니다.

남길 증거

시험 이미지·워커·설정 revision, 선택한 프로필과 지원 판정, 접수/결과 ID, 예약 nextRunAt 전후, 데스크톱·모바일 실제 화면 캡처를 비밀값 없이 기록합니다.
