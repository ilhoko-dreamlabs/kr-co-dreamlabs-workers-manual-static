관리자 설정과 역할 규약

승인된 시험 워커의 중앙 로그인 모드는 CONSOLE_AUTH_MODE=oidc로 선택합니다. 관리자는 전용 OIDC 클라이언트의 HTTPS issuer, 정확한 클라이언트 식별자, HTTPS redirect URI의 /auth/oidc/callback, 서버에 안전하게 주입할 client secret을 운영 절차에서 대조해야 합니다. 비밀값을 Console·브라우저·매뉴얼에 입력하거나 공개하지 않습니다. 실제 설정·주입·워커 활성화는 별도 승인과 사전 점검 뒤에만 진행합니다.

기본 접근 역할은 worker.access, 관리자 역할은 worker.admin입니다. 검증된 ID 토큰에서 해당 클라이언트의 정확한 역할만 사용합니다. 접근 역할이 없으면 입장을 거부하고, 관리자 역할이 없으면 관리 화면과 쓰기를 허용하지 않습니다. groups가 있다면 배열 안의 정확한 blocked 멤버는 역할보다 우선하여 입장을 거부합니다. 대소문자·부분 문자열·경로 정규화를 하지 않습니다. 그룹 값이 없을 때는 그룹 때문에 거부하지 않지만, 잘못된 형식은 거부합니다. 기존 Google 사용자와 같은 이메일이라는 이유만으로 새 OIDC 주체에 권한이나 보존 자료를 자동 이전하지 않습니다.

세션 기본 유휴 시간은 30분이고 절대 상한은 10시간이며, 제공자 만료가 더 빠를 수 있습니다. 기본 메모리 용량은 1,000세션입니다. 서버 재시작·다른 프로세스로의 이동 시 다시 로그인해야 합니다. 이 방식은 영구 로그인이나 다중 프로세스 공유 세션이 아닙니다. 관리자는 해당 워커의 기존 자료와 계정·설정 보존 범위, 역할 매퍼, 현재 작업, 건강 상태를 적용 전에 확인합니다.

사용자 로그인과 세션

  1. 승인된 워커의 /console을 HTTPS로 열고 중앙 로그인 한 가지 방법이 나타나는지 확인합니다. 지정된 계정으로 로그인해 원래 열려고 한 안전한 워커 화면으로 돌아오는지 확인합니다.
  2. 일반 접근 계정은 Chat·프로젝트 등 허용된 기능을 열고, 관리자 계정은 관리 설정을 열어 봅니다. 접근 역할 없는 계정과 정확한 blocked 그룹 계정은 입장이 거부되어야 합니다.
  3. 로그인 상태에서 세션이 갱신되어도 현재 화면이 갑자기 초기화되거나 이미 제출한 쓰기·업로드가 다시 실행되어서는 안 됩니다. 실제 인증 소멸은 401 재로그인으로, 관리자 권한만 줄어든 경우는 403 권한 변경으로 처리합니다.
  4. 로그아웃 뒤 이전 쿠키로 보호된 화면을 다시 열 수 없어야 합니다. 서버 재시작 뒤에는 재로그인해야 하며, 이는 메모리 세션의 의도된 동작입니다.

로그아웃은 워커의 세션을 즉시 제거하지만 상위 IdP의 전체 SSO 로그아웃·토큰 전역 폐기를 보장하지 않습니다. 이미 실행 중인 요청이나 열린 SSE 연결을 즉시 취소한다고 주장하지 않으며, 새 요청과 재연결의 권한을 다시 검사합니다.

화면·초안 복구와 권한 감소

같은 사용자·같은 워커에서 일시적 401을 만났다면 현재 경로와 비밀이 아닌 텍스트 초안은 현재 탭 메모리에서만 보존하고, 다시 로그인한 뒤 정확한 상세 항목을 재조회하여 복원합니다. 제한된 목록에서 항목이 잠시 빠졌다는 이유로 첫 번째 항목을 선택하지 않습니다. 상세 조회가 403/404이면 보호된 내용을 복원하지 않고 접근 불가/항목 없음 상태를 보입니다. 다른 사용자나 다른 워커로 바뀌면 이전 초안과 보호된 화면 내용을 버립니다.

관리자 역할이 없어져 403이 되면 설정 권한을 다시 읽고 관리 상세를 닫되, 사용자를 임의로 로그아웃 처리하지 않습니다. 네트워크 장애나 서버 5xx는 인증 만료의 증거가 아니므로 무조건 로그인 화면으로 보내거나 작업을 재제출하지 않습니다. 외부 SSO의 전체 페이지 이동 중에는 탭 메모리의 초안이 유실될 수 있으므로 화면의 경고를 읽고 필요한 텍스트를 먼저 안전하게 보관합니다. 초안을 브라우저 저장소에 자동 저장하지 않습니다.

탐색·파일 미리보기 보완

목록 또는 SSE 갱신에서 선택 항목이 잠시 보이지 않아도 선택 경로는 유지하지만, 내용은 상세 재조회가 성공한 경우에만 보여 줍니다. Workspace에서 같은 디렉터리를 새로고침해 선택 파일이 계속 목록에 있다면 이미 읽은 미리보기는 이전 내용의 스냅샷으로 남을 수 있습니다. 이는 파일 내용이 새로고침되었다는 뜻이 아닙니다. 아직 읽는 중인 미리보기는 새로고침 때 취소하고 로딩 표시를 끝냅니다. 디렉터리를 바꾸거나 파일이 삭제되면 선택을 해제하고, 취소된 늦은 응답이 화면을 되살리지 않아야 합니다. 탐색기를 닫은 뒤 키보드 초점도 원래 위치로 돌아옵니다. 기본 탐색 절차는 Console Next 사용법을 참고하세요.

확인된 검사와 한계

정확한 소스에서 깨끗한 전체 검사 607건 통과·실패 0·차단 0, 로컬 linux/amd64 이미지 빌드·식별, 정적 자산 1,757개를 확인했습니다. 이미지 CLI는 Codex 0.162.0, Claude Code 2.1.183, Kimi Code 0.29.2입니다. 모의 IdP와 격리 UI/HTTP 검사는 실제 중앙 IdP·사용자 계정·보존 자료를 대체하지 않습니다. 격리 fixture의 기동 준비 확인은 외부 사전 준비가 없어 external_prestart_required와 503으로 남았습니다. 이 결과를 정상 운영 준비 또는 OIDC 기능 실패로 판정하지 않습니다.

Registry 등록, 서버 공급, 업데이트 제안, 지정 워커 적용, 실제 HTTPS 로그인과 인증 갱신은 아직 없습니다. 생산 의존성의 @hono/node-server 중간 심각도 권고도 남아 있어 전면 보안 해결로 표시하지 않습니다. AUTH-C5의 모든 결과는 적용 대상·시각·역할·증거를 적어 통과/실패/차단/미실행으로 각각 판정해야 합니다.

정확한 이미지 적용 뒤 직접 테스트

  1. 시험 워커의 기존 이미지·진행 작업·설정·보존 자료를 기록하고, 전용 IdP 클라이언트와 역할·그룹 매퍼를 읽기 전용으로 다시 확인합니다. 승인된 이미지와 설정을 적용한 경우에만 건강·준비 상태와 보존을 대조합니다.
  2. 관리자, 접근만 가능한 사용자, 접근 역할 없는 사용자, blocked 그룹 사용자의 네 HTTPS 로그인을 각각 시도합니다. 실제 검증된 issuer·subject와 클라이언트 역할, 이전 자료 접근을 비공개 기록에 대조합니다.
  3. 관리자·일반 사용자로 설정 조회/쓰기 권한을 확인합니다. 관리 역할을 줄인 뒤에는 403과 닫힌 관리 상세를, 인증 소멸 뒤에는 401 재로그인을 구분합니다. 같은 이메일의 다른 주체가 이전 초안·보호된 자료를 물려받지 않는지 확인합니다.
  4. 세션 만료·갱신 회전, 로그아웃 뒤 이전 쿠키, 두 탭의 독립성, 승인된 재시작 뒤 재로그인을 검사합니다. 이미 제출한 변경이나 업로드가 갱신·재로그인 때문에 두 번 실행되지 않는지 기록합니다.
  5. 대화 초안과 상세 화면을 연 뒤 목록 갱신·일시적 공백·401 재로그인·403/404·다른 계정 전환을 각각 시험합니다. 전체 페이지 SSO에서 초안 유실 경고와 실제 동작을 확인합니다.
  6. Workspace의 같은 디렉터리 새로고침, 읽는 중인 미리보기 취소, 삭제·디렉터리 이동, 늦은 응답, 키보드 초점을 확인하고 데스크톱·모바일 화면을 민감 정보 없이 촬영합니다.

이 목록은 적용 후 수용 기준입니다. 현재 항목을 통과로 표시할 수 없습니다.

화면 캡처 상태

화면 미촬영 · 이 후보의 실제 워커 화면은 아직 촬영하지 않았습니다. 이전 C10·모의 IdP 화면을 운영 증거로 재사용하지 않습니다. 지정 이미지 적용 후 중앙 로그인, 네 역할의 허용/거부, 401·403, 초안 경고·복구, 목록·파일 미리보기, 로그아웃을 데스크톱과 모바일에서 촬영하고 계정·토큰·비밀값·내부 주소를 가립니다.

정확한 10월 31일 후보의 로컬 이미지·전체 검사를 확인합니다. Registry·서버 공급·워커 적용과 실제 IdP 수용은 아직 없으므로, 아래 기능 검사는 승인된 시험 워커에 정확한 이미지를 적용한 뒤에만 수행합니다.

실행 순서

  1. 전용 OIDC 클라이언트·HTTPS redirect·정확한 역할과 blocked 그룹 매퍼를 읽기 전용으로 확인하고 관리자·접근 계정·접근 불가 계정·차단 계정의 입장 결과를 비교합니다.
  2. 갱신·만료·관리 역할 축소·로그아웃·두 탭·재시작에서 401과 403, 같은 주체의 초안·경로 복구와 다른 주체의 폐기를 확인합니다.
  3. 목록 공백과 파일 미리보기 취소·늦은 응답에서 선택과 내용이 정확한 상세 재조회에 따르는지 확인합니다.
  4. 쓰기·업로드가 자동 재실행되지 않고 전체 페이지 SSO 이동의 초안 유실 경고가 나타나는지 확인합니다.
  5. 승인된 워커의 실제 화면을 비밀값 없이 데스크톱·모바일에서 촬영합니다.
