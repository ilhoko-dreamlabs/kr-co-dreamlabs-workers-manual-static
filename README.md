# 워커 사용자 매뉴얼

공개 사용자 매뉴얼을 위한 정적 기능별 문서입니다. 2026-10-01 실제 실행·화면 증거와 2026-10-08 실행 이미지·소스에서 확인한 변경을 구분합니다. 내부 운영 문서와 원본 캡처는 공개 에셋과 분리합니다.

- 목표 도메인: `manual.workers.dreamlabs.co.kr`
- 현재 단계: 기능별 문서 25개와 페이지별 재현 검사 25개, GitHub Pages 공개 배포
- 기존 촬영 기준: 2026-10-01 KST worker00. 이후 UI가 바뀌어 이 캡처를 최신 화면 증거로 사용하지 않습니다.
- 현재 실행 이미지 확인: 2026-10-08 KST 운영 중인 두 워커가 정상 실행 중입니다. 정확한 배포 식별자는 내부 검증 문서에서 관리합니다.
- 최신 탐색·워커 간 요청·스킬 로딩·전체 업데이트·스킬 설치 화면의 직접 캡처와 사용자 클릭 검증은 아직 확보하지 못했습니다. 페이지별로 미촬영을 표시합니다.

## 실행

```powershell
node scripts/build-sample.mjs
python -m http.server 43817 --bind 127.0.0.1 --directory .
```

브라우저에서 `http://127.0.0.1:43817/guide/`을 엽니다. 빌드는 Node 기본 모듈만 사용합니다. 생성된 HTML, CSS, JavaScript, PNG만으로 동작합니다.

## 편집

- `scripts/build-sample.mjs`, `scripts/full-guides.mjs`, `scripts/latest-guides.mjs`: 문서 내용과 HTML 생성
- `scripts/test-cases.mjs`: 기능별 시작 조건·실행 순서·통과 기준·증거
- `guide/manual.css`: 공통 화면 구성
- `guide/manual.js`: 예제 복사, 캡처 확대
- `assets/screenshots/2026-10-01/`: 공개용 실제 캡처
- `FEATURE_PAGE_MAP.md`: 기능별 문서 확장 계획과 확인 상태
- `MANUAL_TEST_STANDARD.md`: 이후 배포마다 적용할 화면 캡처·실행 검증 기준


생성된 HTML 대신 생성 스크립트를 편집하고 다시 빌드합니다. 기존 버전 캡처는 덮어쓰지 않고 촬영일/제품 릴리스별로 추가합니다. 원본 캡처에는 계정 정보와 다른 작업이 포함될 수 있으므로 공개 저장소에 넣지 않습니다.

## 검증 범위

가상 회의 메모의 요청·결과·후속 요청·세션 검색은 10월 1일 worker00에서 실제 성공 결과까지 확인했습니다. 이후 배포에서 같은 흐름을 다시 검증한 기록은 아닙니다. 예약 생성, 프로젝트 생성, 첨부, 파일 탐색 및 설정 저장은 실제 효과 검증 전입니다. 각 페이지의 검사 절차는 독자가 재현하기 위한 지침이며 통과 기록이 아닙니다. 새로운 UI의 스크린샷은 현재 연결된 브라우저가 없어 미촬영입니다. 내부 설정 10개 탭의 자세한 사용법과 캡처는 공개 저장소 밖의 운영 문서에 있습니다.

## 다음 구현 단계

1. 동일한 문서 형식으로 실제 기능을 하나씩 실행·검증하고 캡처합니다.
2. 제품 릴리스 식별자와 변경 기능 목록을 확정해 문서·캡처·변경 이력을 연결합니다.
3. 워커 배포와 문서 변경 이력의 버전 연계를 자동화합니다.

배포마다 문서 영향 검사를 하고, 변경이 없는 기능도 해당 버전에서 확인한 상태를 기록합니다. 현재 변경 이력 페이지는 문서 제작 기록을 표시합니다. 제품 버전별 이력과 배포 자동 연계는 정식 버전 기준이 확정된 뒤 구현합니다.
